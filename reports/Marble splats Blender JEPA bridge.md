# Blender Carries Marble's Splats, JEPA Stays Theory

**(1) World Labs and Marble.** World Labs, co-founded by Fei-Fei Li, Justin Johnson, Christoph Lassner and Ben Mildenhall ([Maginative](https://www.maginative.com/article/world-labs-emerges-from-stealth-with-230-million-to-build-spatial-intelligence-ai/)), sells **Marble, a multimodal model that turns text, images, video, panoramas or coarse 3D layouts into persistent, downloadable 3D worlds** delivered as Gaussian splats plus collider meshes ([World Labs](https://www.worldlabs.ai/blog/marble-world-model)). Its architecture is undisclosed and no Marble paper was found; the World API (21 Jan 2026) is asynchronous and polling-only, the one announced next step is the Atlas "omni" model (1 Sep 2026), and AMD's roughly **$8.2B all-stock acquisition (announced 28 Sep 2026) is widely reported but still pending** ([AMD Newsroom](https://newsroom.amd.com/news/amd-acquire-world-labs/)). **(2) Blender as hub.** The bridge works today but is lopsided: Blender 5.3 (stable release scheduled 10 Nov 2026) imports PLY, SPZ and USD splats natively but **cannot export them** ([Cinevva](https://app.cinevva.com/news/2026-09-16-blender-5-3-gaussian-splats)), so the return leg runs through add-ons that write INRIA PLY, then PlayCanvas splat-transform to ratified GLB with `KHR_gaussian_splatting`, SOG or SPZ ([KHR README](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_gaussian_splatting/README.md)), and the user's x3d-blender-io fork for the X3D 4.1 `GaussianSplats` node that X_ITE renders ([X_ITE docs](https://github.com/create3000/x_ite/blob/main/docs/_posts/components/GaussianSplats/GaussianSplats.md)); Marble's export axis convention is unresolved in the sources and needs a test import. **(3) JEPA.** No organizational link between Yann LeCun's AMI Labs and World Labs was found (NVIDIA invests in both); the relationship is conceptual, a generative explicit-3D world model versus a predictive latent one, and the adjacent evidence (NVIDIA's Marble-to-Isaac Sim pipeline, splat-based robot simulators, Gaussian-JEPA on object-level splats, V-JEPA 2.1's depth probe) never joins the two: **no one has trained or evaluated a JEPA on Marble worlds** ([NVIDIA](https://developer.nvidia.com/blog/simulate-robotic-environments-faster-with-nvidia-isaac-sim-and-world-labs-marble); [Gaussian-JEPA](https://arxiv.org/abs/2608.15651)). **(4) AI-enabled X3D.** The parts exist (x3d_mcp's four-layer validation, X_ITE's splat node, Blender MCP, simulator-in-the-loop critics) but no published system combines agents, a scene graph, splats and JEPA ([x3d_mcp](https://github.com/Web3DConsortium/x3d_mcp)); the closing PROPOSAL specifies role-scoped agents behind a validated, signed, transactional edit layer, with a JEPA-style critic as a gated research stage rather than a dependency.

## Marble discloses its outputs but not its architecture

World Labs has documented Marble's interface in detail and its internals not at all. Inputs are text, a single image, multiple images (each with an optional azimuth), video, a panorama or a coarse 3D layout ([World Labs blog](https://www.worldlabs.ai/blog/marble-world-model); [API quickstart](https://docs.worldlabs.ai/api)) [S]. Chisel, flagged experimental, separates structure from style: the user blocks out boxes, planes, walls or imported GLB/FBX assets and a text prompt sets the look ([Chisel basics](https://docs.worldlabs.ai/marble/create/chisel-tools/chisel-basics)) [S]. Outputs are splats as SPZ ("Marble's native splat format") or PLY at about 2M splats full-resolution or about 500k, a 2560 x 1280 equirectangular panorama, a coarse collider GLB, and a high-quality GLB that the docs say is **derived from the splat**, so reconstruction artifacts are expected ([Export specs](https://docs.worldlabs.ai/marble/export/specs); [Mesh export](https://docs.worldlabs.ai/marble/export/mesh)) [S]. The model line is `marble-1.0-draft`, `marble-1.0`, `marble-1.1` and `marble-1.1-plus`; Plus grows a world by "dynamic cubes", described by press as up to five extra spatial units at 300 credits each ([Radiance Fields](https://radiancefields.com/world-labs-releases-marble-1.1-and-marble-1.1-plus)) [T]. Region-selective Expand and a Composer that assembles several worlds into one space come from an announcement summary ([visual-slam-roadmap](https://github.com/changh95/visual-slam-roadmap/blob/main/level-11-world-models-spatial-ai/world-labs-marble.md)) [T].

What is missing is the substance of a technical report. No Marble paper, benchmark, model code or weights were located, and World Labs' GitHub organization holds an API client, examples, agent skills, `atlas-camera-studio` and `marble-multiview-inpainting` but no research code ([github.com/worldlabsai](https://github.com/worldlabsai)) [D]. The question of whether the network emits splat parameters directly is open: a third-party write-up of the Latent Space interview paraphrases Johnson as saying Marble natively outputs Gaussian splats, while another summary has him arguing splats are only the current atomic unit ([Riffon](https://riffon.com/insight/ins_58co5iqjaxj5); [Latent Space](https://www.latent.space/p/after-llms-spatial-intelligence-and)) [T]. A reported September 2026 podcast has Johnson saying Marble bottlenecked every output through splats and that Atlas makes new-view prediction the core primitive, generating splats only when needed, but that is a single secondary source ([My Living AI](https://www.mylivingai.com/nobody-agrees-what-a-world-model-is-justin-johnson-world-labs-explains-why/)) [T].

**Inference.** The disclosed artifacts point toward "generate consistent views plus depth, then lift to splats". Panorama is a first-class export, and the Atlas-era APIs expose posed RGB-D primitives: `images2PosedRGBD` returns an EXR depth map and camera poses, `atlasGenerate` returns camera-conditioned frames, and the inpainting tool takes 2 to 16 posed RGB-D views plus depth as EXR, NPY or NPZ ([atlas-camera-studio](https://github.com/worldlabsai/atlas-camera-studio); [marble-multiview-inpainting](https://github.com/worldlabsai/marble-multiview-inpainting)) [D]. Fixed output tiers of roughly 2M, 500k and 100k splats and a flat 1,500-credit price suggest bounded, fixed-cost inference rather than per-scene optimization. The nearest published families are CAT3D (multi-view diffusion then reconstruction, with Mildenhall as co-author), Lyra (a video-diffusion latent decoded to 3DGS), Bolt3D and feed-forward lifters such as VGGT and GS-LRM ([CAT3D](https://arxiv.org/abs/2405.10314); [Lyra](https://arxiv.org/pdf/2509.19296v1); [VGGT](https://arxiv.org/abs/2503.11651)) [M/S]. An independent critique of Atlas launch material argues depth maps and images are turned into splats after generation ([Bret Kerr](https://bretkerr.substack.com/p/a-gaussian-splat-is-a-transparent)) [T], but it concerns Atlas, not Marble. **Speculation.** The most parsimonious pipeline is prompt, then panorama or multi-view diffusion with depth, then a feed-forward or short-optimization splat lift, then LoD downsampling and mesh baking; the "Marble 5 API" wording in the `atlas-camera-studio` README hints that the Atlas backbone already sits behind Marble-branded endpoints. Neither has direct evidence.

The representation itself is well understood **[M]**. NeRF (Mildenhall et al., 2020) stores a scene as an MLP mapping position and direction to density and view-dependent colour, rendered by volumetric ray marching and trained per scene ([arXiv 2003.08934](https://arxiv.org/abs/2003.08934)); Instant-NGP's hash grid cut training to seconds or minutes ([arXiv 2201.05989](https://arxiv.org/abs/2201.05989)). 3D Gaussian Splatting (Kerbl et al., 2023) replaced the implicit field with millions of explicit anisotropic Gaussians, each carrying a position, a scale-and-quaternion covariance, an opacity and spherical-harmonic colour (about 59 floats at SH degree 3), rasterized through depth-sorted tiles at real-time rates ([arXiv 2308.04079](https://arxiv.org/abs/2308.04079)). **Inference:** explicit primitives are why splats are editable, streamable and LoD-able where NeRFs are not, and why a generator that must hand assets to engines would pick them. The cost is baked lighting, no guaranteed surface (hence "derived" meshes), floaters and aliasing.

RTFM and Atlas are different bets from Marble. RTFM is an autoregressive diffusion transformer trained end-to-end on video that builds no explicit 3D representation; its world is the KV-cache of pose-tagged frames, with "context juggling" retrieving spatially nearby frames ([RTFM blog](https://www.worldlabs.ai/blog/rtfm); [Radiance Fields](https://radiancefields.com/world-labs-announces-realtime-frame-model-(rtfm))) [S]. **Inference:** Marble's persistence is asset-level (the splat file is the world state, so it renders identically from any pose), whereas RTFM's is context-level and can drift after long excursions. Atlas is reported as a multimodal autoregressive diffusion transformer (rectified flow) that takes camera geometry as an input and returns up to about a minute of 1440p video or point clouds and splats, with World Labs claiming it beats specialized models and independent commentary questioning benchmark fairness ([Kingy AI](https://kingy.ai/blog/world-labs-atlas-world-model-deep-dive/); [Winzheng](https://www.winzheng.com/en/article/world-labs-atlas-omni-world-model-spatial-intelligence-launc)) [T]; World Labs says Atlas "will power future versions of Marble" ([Radiance Fields](https://radiancefields.com/world-labs-announces-new-world-model-atlas)) [T].

Spark is the best-documented piece because it is open source **[D]**. It renders all splats in one instanced draw call after a background-worker bucket sort whose order "lags the render by at least one frame", merges with mesh geometry through the Z-buffer, and supports per-splat transforms, skinning and procedural splats ([system-design](https://github.com/sparkjsdev/spark/blob/main/docs/docs/system-design.md)). Version 2.0 added a hierarchical LoD tree, the streamable `.RAD` format fetched by HTTP range requests, and a shared GPU page table (default 16M splats) intended for scenes of 100M or more splats; World Labs' own splat budgets are about 1M for Quest 3, 1 to 3M for phones and 1 to 5M for computers ([new-features-2.0](https://github.com/sparkjsdev/spark/blob/main/docs/docs/new-features-2.0.md); [performance](https://github.com/sparkjsdev/spark/blob/main/docs/docs/performance.md)). The compact `PackedSplats` encoding stores centres as float16, which loses precision away from the origin; the 32-byte `ExtSplats` added in 2.0 uses float32 centres ([packed-splats](https://github.com/sparkjsdev/spark/blob/main/docs/docs/packed-splats.md)). **Inference:** a full-resolution Marble world (about 2M splats) fits the desktop budget but not Quest or phones without the 500k tier or LoD.

Marble's limits are the limits of a generated, splat-based asset. Worlds are plausible rather than metric: hidden regions are invented, and a World Labs essay warns that generated geometry can look right while having self-intersections or wrong scale that produce nonsensical physics ([taxonomy essay, via search summary](https://www.worldlabs.ai/blog/taxonomy-of-world-models)) [S]. The docs concede "uneven geometry, holes, and blobby or 'floater' surfaces" in derived meshes and call colliders simplified ([Mesh export docs](https://docs.worldlabs.ai/marble/export/mesh)) [S]; an independent hands-on test found lower quality away from the input viewpoint, poor overlap when splats and conventional meshes share a scene, odd collision behaviour and weak early mesh quality ([design4real](https://design4real.de/en/world-labs-marble-practical-test/)) [T]. Worlds are static (dynamics appear only in post-processed export videos), splats carry no semantic, instance or material labels, lighting is baked into view-dependent colour, and no quantitative accuracy study exists ([Latent Space](https://www.latent.space/p/after-llms-spatial-intelligence-and); [SPARK_V2.md](https://github.com/sandraschi/worldlabs-mcp/blob/main/docs/SPARK_V2.md)) [T]. **Inference:** treat Marble as a generator of visual scenes with coarse proxies, not of simulation-ready worlds; physics, semantics and metric scale must be added downstream.

## The World API is an asynchronous REST service with a thin public roadmap

The World API launched on 21 Jan 2026 as a REST service at `https://api.worldlabs.ai/marble/v1/...`, authenticated with a `WLT-Api-Key` header ([Generate reference](https://docs.worldlabs.ai/api/reference/worlds/generate)) [S]; the official Python client README confirms the header ([worldlabs-api-python](https://github.com/worldlabsai/worldlabs-api-python)) [D]. The documented flow is: get a key and buy credits at platform.worldlabs.ai, POST `worlds:generate`, poll the returned operation until it is done, then GET the world ([Quickstart](https://docs.worldlabs.ai/api)) [S]. The request body takes `display_name`, `model`, `permission`, `seed`, `tags` and a `world_prompt` discriminated by `type`: `text` (with a `disable_recaption` flag), `image` (with `is_pano` defaulting to `auto`, so a valid equirectangular image skips the panorama-generation step), `multi-image` (an array of images with optional `azimuth`) and `video`. Generation usually takes about five minutes; polling is free; and errors are 400 (invalid request, policy violation or bad `model`), 402 (insufficient credits), 429 (rate limit) and 500 ([Rate limits](https://docs.worldlabs.ai/api/rate-limits)) [S]. Machine-readable indexes live at `/llms.txt` and `/llms-full.txt` ([llms-full.txt](https://docs.worldlabs.ai/llms-full.txt)) [S]. No official webhook was found; every excerpt uses polling, although one press summary mentions a callback ([blockchain.news](https://blockchain.news/ainews/world-labs-launches-world-api-to-integrate-marble-ai-into-products-and-workflows)) [T].

A completed world exposes `assets.imagery.pano_url`, `assets.splats.spz_urls` (keys `100k`, `500k`, `full_res`), `assets.splats.semantics_metadata` (including `metric_scale_factor` and `ground_plane_offset`) and `assets.mesh.collider_mesh_url` ([Quickstart](https://docs.worldlabs.ai/api); [Get a world](https://docs.worldlabs.ai/api/reference/worlds/get)) [S]. The export call converts SPZ splats to a cached PLY (`{"asset_type":"splats","format":"ply","resolution":"full_res"}`, usually returned already done with a signed URL) or starts the high-quality GLB mesh, which the app docs limit to four requests an hour with up to an hour of processing ([FAQ](https://docs.worldlabs.ai/api/faq); [Export specs](https://docs.worldlabs.ai/marble/export/specs)) [S]. Signed URLs expire, so a pipeline must cache what it downloads ([sceneview PR #3751](https://github.com/sceneview/sceneview/pull/3751)) [T]. Splats come in arbitrary model units, not metres, which is why `semantics_metadata` exists: apply `metric_scale_factor`, then the ground offset ([Export specs](https://docs.worldlabs.ai/marble/export/specs)) [S]. The axis convention conflicts across sources and is treated in the Blender section. **Not found:** SH degree and colour space of Marble files, glTF or USD export, and whether `:export` costs credits.

Money and rules are the constraints that shape an agent loop. API credits cost $1.00 per 1,250 ($5 minimum), never expire and cannot be bought through the Marble app; a standard world costs 1,500 credits, a text prompt adds an 80-credit panorama step, draft costs 150, and Plus adds up to 1,500 more ([API pricing](https://docs.worldlabs.ai/api/pricing)) [S]. **Inference:** at the published rate a standard world is about $1.20, a draft about $0.12 and a worst-case text-prompted Plus world 3,080 credits, about $2.46. Default limits are about three starts a minute and 60 an hour, with approved accounts reaching about 30 standard and 90 draft starts a minute; a 429 means the start was not accepted ([Rate limits](https://docs.worldlabs.ai/api/rate-limits)) [S]. ## Blender can be the hub, but only the import leg is native

Blender is a credible transmission point because its input side has just become first-class and its output side is rich in add-ons, but the two halves come from different places and the seam between them is where errors hide. The user's own repository supplies the X3D half; the web, Unreal, Unity and Omniverse halves come from third-party tools and Khronos, PlayCanvas and NVIDIA formats.

### Blender 5.3 imports splats but does not export them

Blender's main branch gained "implements importing gaussian splats from PLY" and "makes the Import PLY node handle gaussian splats" on 16 Sep 2026 and "sanitizes the SPZ and PLY importers against malformed files" on 17 Sep, with PLY robustness fixes still landing on 20 to 21 Oct ([blender/blender commits](https://github.com/blender/blender/commits/main/source/blender/io/ply)) [D]. The release notes, seen only through summaries, say Workbench, EEVEE and Cycles render splats with an emissive default shader and a `radiance` attribute, relighting is "rudimentary", and three limits apply: performance is "not ideal", splats are assumed sRGB while Cycles and EEVEE work in linear, and **Apply Transform does not yet handle the new scale, rotation and spherical-harmonics attributes** ([Blender 5.3 rendering notes](https://developer.blender.org/docs/release_notes/5.3/rendering/)) [S]. Secondary coverage adds that PLY and SPZ (up to v4, with automatic coordinate conversion) import, that splats live as a new "3D Gaussian Splat" Point Cloud type operated on by Geometry Nodes (new Import SPZ and Set Point Cloud Type nodes), that USD `ParticleField` splats import, and that **there is no splat export** ([Digital Production](https://digitalproduction.com/2026/09/22/blender-5-3-brings-gaussian-splats-home/); [Cinevva](https://app.cinevva.com/news/2026-09-16-blender-5-3-gaussian-splats)) [S]. Stable release is scheduled for 10 Nov 2026, so Blender 5.3 is unreleased on 22 Oct and no release-candidate report was found. Blender's notes describe the splat convention as "Z as the Forward Axis, -Y as Up axis" and warn that SPZ files saved outside the SPZ convention may need manual rotation ([Blender 5.3 rendering notes](https://developer.blender.org/docs/release_notes/5.3/rendering/)) [S]. No evidence was found of `KHR_gaussian_splatting` support in the `KhronosGroup/glTF-Blender-IO` add-on, so GLB splat files must be written outside Blender.

The add-on ecosystem fills the export gap unevenly. KIRI's **3DGS Render** (repository page says GPL-2.0; 1.2k stars) imports 3DGS PLY, edits with Blender selections and modifiers, composites splats with Blender scenes, **exports edited 3DGS and animated PLY sequences**, rotates SH on bake in 5.1.0, and is "moving into community-led maintenance" ([repo](https://github.com/Kiri-Innovation/3dgs-render-blender-addon); [releases](https://github.com/Kiri-Innovation/3dgs-render-blender-addon/releases)) [D]. **Gaussian Splat Patch** (Blender 5.3+ extension, GPL-3.0, built against the 5.3 alpha) erases, clones, heals and merges splats while rotating SH bands 1 to 3, and exports standard INRIA PLY ([repo](https://github.com/timfennell/blender-splat-patch)) [D]. AssetKit's Blender extension imports SPZ, L-GSC and Gaussian PLY/glTF for preview only ([release v0.3.0](https://github.com/recp/assetkit-blender/releases/tag/v0.3.0)) [D]; `blender-splat-render` adds SH relighting but is early ([repo](https://github.com/timfennell/blender-splat-render)) [D]; PLAN8VR's exporter writes synthetic splat PLY from mesh geometry ([repo](https://github.com/PLAN8VR/blender-splat-exporter)) [D]; and Gauss Cannon and BlenderNeRF export COLMAP or NeRF-style datasets for retraining ([Gauss Cannon](https://github.com/warpgatelabs/gauss-cannon); [BlenderNeRF](https://github.com/maximeraafat/BlenderNeRF)) [D]. Paid options such as SplatForge and Fast Splatting rest on vendor claims ([Superhive](https://superhivemarket.com/products/splatforge)) [V]. No Blender splat-to-mesh add-on was verified; Houdini's GSOPs bake splats to points, meshes and density volumes ([GSOPs](https://github.com/cgnomads/GSOPs)) [D]. **Inference:** the hub is an ingest, align and clean hub with a bring-your-own export, and a native exporter in 5.4 or later would be the largest single improvement (**Speculation** on timing).

**The reverse leg, from engines and tools into Blender, is narrower.** Blender's native importers take PLY, SPZ (to v4) and USD `ParticleField`, so splats trained or exported by 3DGRUT (USD, NuRec USDZ or PLY), LichtFeld Studio (PLY, SOG, SPZ) or SuperSplat arrive as PLY, SPZ or USD ([3DGRUT](https://github.com/nv-tlabs/3dgrut/blob/main/README.md); [LichtFeld Studio](https://github.com/MrNeRF/LichtFeld-Studio); [SuperSplat](https://github.com/playcanvas/supersplat/releases)) [D]. No verified Blender importer exists for SOG, `.rad` or GLB with `KHR_gaussian_splatting` (AssetKit previews glTF splats only), so web-delivery files must be converted back to PLY first, and `splat-transform` cannot read GLB at all, which means the hub needs its own GLB reader or gsbox, which reads GLB from v4.7.1 ([splat-transform](https://github.com/playcanvas/splat-transform/blob/main/README.md); [gsbox](https://github.com/gotoeasy/gsbox/blob/main/README.md)) [D]. From engines, Unity's aras-p plugin documents a world-space export that bakes position, rotation and scale into a PLY with SH rotation ([DeepWiki](https://deepwiki.com/aras-p/UnityGaussianSplatting)) [S]; no verified splat export was found for Unreal; and X3D scenes return through x3d-blender-io, whose round trip is tested bit for bit.

**Table 2. Conversion recipe**

| Step | Action | Why | Tag |
|---|---|---|---|
| 1. Fetch and pin | Set `model` explicitly (use `marble-1.0-draft`, 150 credits, for tests); poll; download SPZ tiers and the collider GLB; request PLY through `:export`; store `semantics_metadata`; cache with content hashes | Signed URLs expire; the default model is documented inconsistently | S |
| 2. The Marble axis question deserves its own treatment because every later step depends on it. World Labs release notes reportedly say worlds export in OpenGL coordinates rather than OpenCV for splats and meshes, with the date given as Dec 2025 in one place and Jan 2026 in another and an OpenGL-versus-OpenCV choice added on 1 Jan 2026 ([release notes](https://docs.worldlabs.ai/marble/release-notes)) [S]; older export guidance says default worlds are OpenCV and that DCC tools need Y and Z scaled by -1 ([Exporting from Marble](https://docs.worldlabs.ai/marble/export/gaussian-splat/index)) [S]; and a June 2026 trade-press piece says default worlds are OpenCV and the correction is to negate Y and Z ([Digital Production](https://digitalproduction.com/2026/06/04/image-blaster-turns-images-into-splats/)) [S]. **Unresolved.** **Inference** (engine conventions here are general knowledge, not World Labs statements): if a file is OpenGL-style (Y-up, right-handed, camera looking down -Z), three.js and Spark need no axis change, Blender needs a +90° rotation about X and Unity needs a handedness mirror; if it is still OpenCV, apply the documented Y and Z negation first. The sources cannot settle which applies to a given download, so the first step of the recipe is a test, and a draft-model test world costs about $0.12.

**Where transforms, units and handedness live.** In Blender, keep rotation and scale on parent empties or object transforms and do not apply them, because Apply Transform skips the splat attributes ([Blender 5.3 notes](https://developer.blender.org/docs/release_notes/5.3/rendering/)) [S]. In X3D, put the transform on a `Transform` above the `Inline`, as x3d-blender-io does when it carries Blender's Z-up as a Y-up rotation ([README](https://github.com/hagopjay/x3d-blender-io)) [D]. In glTF, leave it on the node, since the extension rotates SH by the node rotation ([KHR README](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_gaussian_splatting/README.md)) [D]. Bake only in a tool that rotates SH explicitly: 3DGS Render's bake and Patch's merge do, while splat-transform's documentation does not say ([3DGS Render releases](https://github.com/Kiri-Innovation/3dgs-render-blender-addon/releases); [Patch](https://github.com/timfennell/blender-splat-patch); [splat-transform](https://github.com/playcanvas/splat-transform/blob/main/README.md)) [D]. For units, Blender works in metres, x3d-blender-io multiplies splat scales by the unit factor on import, and `blender-splat-render` needs Blender's unit scale set to the real scene size for correct depth of field ([PR #12](https://github.com/hagopjay/x3d-blender-io/pull/12); [repo](https://github.com/timfennell/blender-splat-render)) [D]. For handedness, Unity and Unreal are left-handed while Blender, glTF and three.js are right-handed, so a mirror, not just a rotation, is needed for the first two, and Babylon.js performs no conversion at all ([Babylon doc](https://github.com/BabylonJS/Documentation/blob/master/content/features/featuresDeepDive/mesh/gaussianSplatting.md)) [D / general engine knowledge].

### The user's x3d-blender-io fork already covers the X3D spoke, with three README contradictions to fix

`hagopjay/x3d-blender-io` (a fork of the Web3D X3D Blender add-on; GPL-3.0; Blender 4.2+, verified on 5.2 per its README) exports splat objects as the X3D 4.1 draft `GaussianSplats` node, falls back to a coloured `PointSet` under X3D 4.0, imports `.ply` and `.splat` through Inline, reads and writes INRIA PLY and 32-byte `.splat` without bpy, writes quaternions as x,y,z,w to match glTF (data in w,x,y,z order renders as streaks in X_ITE), maps Blender's Z-up into X3D's Y-up with an Inline Transform, and emits whole SH degrees only ([README](https://github.com/hagopjay/x3d-blender-io)) [D]. PR #12 (merged 12 Oct 2026, v2.6.1) fixed an Expat 2.6+ deferral that made X3D 4.1 files above roughly 18,000 splats import as empty scenes while reporting success, replaced `%.6f` text (which zeroed 188 of 398,769 small scale components) with shortest round-trip `%g`, made NaN and Inf abort export, and verified that a real 132,923-splat SH3 file (74 MB) round-trips bit-identically in 10.7 s ([PR #12](https://github.com/hagopjay/x3d-blender-io/pull/12)) [D]; the README reports X_ITE 16.4.3 rendering a 500,000-splat scene the add-on wrote. **Inference:** any XML-parsing tool in an agent chain should be tested with multi-megabyte start tags before agents are trusted with splat-bearing scenes.

Three statements need reconciling. First, the README says in one place that Blender 5.3 native splat point clouds are exported, in its known-caveats that native 5.3 splat objects "are not read yet because that API is still in alpha", and elsewhere that the 5.3+ importer reads the node back ([README](https://github.com/hagopjay/x3d-blender-io)) [D]. Third, PR #5 says the node was "added to the draft on 2026-09-29", but an April 2026 x3d-public thread already discussed a proposed node and X_ITE shipped it in May, so that date is at most a later draft revision and is unverified ([x3d-public, Apr 2026](https://web3d.org/pipermail/x3d-public_web3d.org/2026-April/022411.html)) [S]. The fix is to state one Blender 5.3 read/write position and to cite X_ITE 15.1 as the first implementation.

## No one has joined Marble and JEPA, but the pieces sit side by side

**Verdict.** The notes found no organizational, advisory, investor or collaborative link between Yann LeCun's AMI Labs and Fei-Fei Li's World Labs. Public pairing of the two is third-party framing ([EntropyTown](https://entropytown.com/articles/2025-11-13-world-model-lecun-feifei-li/); [Hacker News](https://news.ycombinator.com/item?id=45923326)) [T]. The negative is search-limited: the full texts of Li's essays, the taxonomy post and the Latent Space and a16z podcasts were not scanned for the words JEPA, LeCun or AMI, and posts on X, LinkedIn and Threads are not indexed by the search tool. AMI Labs raised about $1.03B at a $3.5B pre-money valuation (announced 9 to 10 Mar 2026) under CEO Alexandre LeBrun, with LeCun as executive chairman and a CEO statement of "at least a year of research before deploying our first real-world applications" ([TechCrunch](https://techcrunch.com/2026/03/09/yann-lecuns-ami-labs-raises-1-03-billion-to-build-world-models/); [Futurum](https://futurumgroup.com/insights/yann-lecuns-ami-raises-1bn-seed-round-is-the-world-model-era-finally-here/)) [T]. **Inference:** AMD's purchase of World Labs pulls World Labs toward AMD's ecosystem while NVIDIA backs AMI, which weakens even the shared-investor story.

**The conceptual divide is generative explicit 3D versus predictive latent state.** A JEPA predicts the representation of a hidden or future part of the input from a visible context instead of reconstructing pixels or tokens, and needs a regularizer or architectural trick to stop embeddings collapsing; LeCun's 2022 position paper places it inside a modular agent (perception, world model, cost with a trainable critic, actor, memory, configurator) that plans by minimizing cost over predicted latent futures ([OpenReview PDF](https://openreview.net/pdf?id=BZ5a1r-kVsf); [Shaped](https://www.shaped.ai/blog/yann-lecun-a-path-towards-autonomous-machine-intelligence)) [S]. Marble does the opposite on each axis that matters here: it generates an explicit, inspectable asset that a human or engine renders. Analysts frame the split as whether a world model is something you look at or something an agent plans with ([Eka Ventures](https://ekavc.substack.com/p/world-models-impact-edition)) [T], and one critique argues Marble models only the part of the world people can see ([EntropyTown](https://entropytown.com/articles/2025-11-13-world-model-lecun-feifei-li/)) [T]. An academic roadmap places the JEPA family in the "latent-space simulator" category of world models ([arXiv 2607.06401](https://arxiv.org/pdf/2607.06401)) [S]. **Inference:** a JEPA-style model fits the planner and latent-simulator slots of World Labs' renderer, simulator and planner taxonomy, though World Labs never made that placement. Both camps reject the LLM-only path, and Li has argued that a robot unable to predict what happens when a cup falls off a table cannot work effectively in the real world ([The Neuron](https://www.theneuron.ai/newsletter/dr-fei-fei-li-the-godmother-of-ai-on-why-we-need-spatial-intelligence/)) [T], a prediction claim that LeCun would plausibly share (**Inference**). The JEPA line itself matured within a year: LeJEPA's SIGReg regularizer (Nov 2025), LeWorldModel (Mar 2026; about 15M parameters, one GPU, end-to-end from pixels) and H-JEPA (Oct 2026), a hierarchical model whose three-level version reached 73.3% success on Visual AntMaze against 18.0% for flat LeWM ([LeJEPA](https://arxiv.org/abs/2511.08544); [LeWM](https://arxiv.org/pdf/2603.19312v2); [H-JEPA](https://arxiv.org/html/2610.06805)) [S].

**NeRF and splats connect through lineage and simulators, not through JEPA.** Mildenhall created NeRF and co-authored CAT3D and DreamFusion, and two searches found **no paper combining JEPA with NeRF** ([NeRF](https://arxiv.org/abs/2003.08934); [CAT3D](https://arxiv.org/abs/2405.10314)) [M]. **Inference:** splats have largely replaced NeRF in the robot-simulation work cited here because 3DGS renders in real time and edits per primitive ([3DGS](https://arxiv.org/abs/2308.04079)) [M]. JEPA has met 3D elsewhere. Point-JEPA and 3D-JEPA work on point clouds ([Point-JEPA](https://arxiv.org/pdf/2404.16432); [3D-JEPA](https://arxiv.org/pdf/2409.15803)) [S]. **Gaussian-JEPA** (arXiv 2608.15651, Aug 2026) predicts held-out Gaussian-token blocks in representation space on ShapeNet splat assets and reports more consistent features than a matched Gaussian-MAE; it is object-level, comes from neither LeCun's team nor Meta nor AMI, and its numbers were not retrieved ([arXiv](https://arxiv.org/abs/2608.15651); [Radiance Fields](https://radiancefields.com/papers/gaussian-jepa-joint-embedding-predictive-learning-for-3d-gaussian-splats)) [S].

**On depth, physics and dexterity the JEPA evidence is real but narrow.** For depth, V-JEPA 2.1 (Mar 2026) reports 0.307 RMSE on NYUv2 monocular depth with a linear probe, the strongest evidence that a JEPA video encoder keeps metric-like 3D structure without 3D supervision, though a probe is not reconstruction or novel-view synthesis ([BDTechTalks](https://bdtechtalks.com/2026/03/23/v-jepa-2-1/); [Meta README](https://cdn.jsdelivr.net/gh/facebookresearch/vjepa2@main/README.md)) [S]. For physics, LeWM's latent reportedly encodes physical structure and a "surprise" evaluation flags physically implausible events ([LeWM](https://arxiv.org/pdf/2603.19312v2)) [S]. For dexterity, V-JEPA 2-AC was post-trained on under 62 hours of Droid robot video after pretraining on over 1M hours of internet video, then drove Franka arms zero-shot in two labs on pick-and-place with image goals, planning with cross-entropy search over latent futures and re-planning after each action; reported limits are camera-position sensitivity and long-horizon planning ([arXiv 2506.09985](https://www.arxiv.org/pdf/2506.09985)) [S]. That is gripper-level pick-and-place, not in-hand dexterity. No published JEPA result shows long-horizon real-world manipulation or navigation, the success rates attributed to V-JEPA 2-AC (about 80% for pick-and-place) come from one secondary source, and V-JEPA 2.1's reported "20-point" real-robot grasp gain is ambiguous between points and percent ([Emergent Mind](https://api.emergentmind.com/topics/v-jepa-2)) [T]. On the Marble side, worlds are static with a coarse collider, depth falls out of splat rasterization, and the SceniX acquisition aims at real-to-sim-to-real policy training rather than latent prediction ([GaussGym](https://arxiv.org/pdf/2510.15352); [World Labs](https://www.worldlabs.ai/blog/real-to-sim-to-real)) [S].

**What actually connects them is simulation.** NVIDIA's developer blog documents Marble PLY splats plus a GLB collider converted to USD and imported into Isaac Sim ([NVIDIA](https://developer.nvidia.com/blog/simulate-robotic-environments-faster-with-nvidia-isaac-sim-and-world-labs-marble)) [S]; RoboGSim and GaussGym use 3DGS as the renderer inside physics simulators, GaussGym at over 100,000 steps a second with depth from rasterization ([RoboGSim](https://arxiv.org/pdf/2411.11839); [GaussGym](https://arxiv.org/pdf/2510.15352)) [S]; and the Gaussian World Model (GWM) compresses Gaussians into a latent space and predicts future Gaussians with a latent diffusion transformer, so it is a latent Gaussian world model on the generative side of the divide, a reminder that latent does not mean JEPA ([GWM](https://arxiv.org/pdf/2508.17600)) [S]. **Inference**, ordered by strength of evidence: splat scenes as a simulation and evaluation substrate for a latent world model are best supported, and LeWM and DINO-WM are cheap enough to use that way; rendered splat tours as a data source with exact poses and depth are weaker because of static scenes, baked lighting and the gap to 1M hours of real video; splats as a structured input prior are least supported, since Gaussian-JEPA shows only that splats can be tokenized for self-supervised learning. **Speculation:** an AMI-style system could use Marble-like scenes purely as an offline data generator while keeping its own representation non-generative at inference, which would fit LeCun's objection to generating pixels as the model's mechanism; no source shows him endorsing it.

## Conclusion

The strongest result is a standards convergence, not a Marble-to-JEPA link. glTF's ratified splat extension, the X3D node that mirrors it field for field and OpenUSD's `ParticleField` schema all describe the same Gaussian data, so a hub that normalises conventions once at ingest and proves every spoke by round trip can be correct in a way no single engine plugin guarantees. Blender's job is ingest, alignment and cleaning with export left to add-ons, and the practical dangers are silent convention errors (axes, quaternion order, SH rotation, activation functions, Apply Transform) rather than missing features. That is why the recipe starts with a $0.12 asymmetric-marker test and ends with a bit-exact round trip, the discipline the user's own PR #12 already applied to X3D.

The JEPA question changes shape once the evidence sits side by side. Marble supplies static, visually rich worlds with coarse colliders; JEPA models learn dynamics from action-conditioned experience; the missing ingredient on both sides is dynamics, which only a physics simulator supplies. The first defensible role for a JEPA-style model here is therefore as a critic or planner over simulator rollouts in Marble-derived scenes, not as an editor of a scene graph, and nothing published tests even that. Whether such a critic beats a physics check plus a debiased VLM judge is an empirical question, so the proposal below turns it into a go/no-go gate. Platform risk (the AMD close, Atlas reshaping Marble's endpoints) argues for an adapter layer and local caching from the first day.

## PROPOSAL: role-scoped agents inside a validated X3D scene graph, with a gated JEPA critic

This section is a design proposal, not a finding. Each element carries one label: **Grounded** (a cited source demonstrates the component or pattern), **Inference** (reasoned from cited evidence but not demonstrated) or **Speculation** (plausible, with no direct evidence). The survey behind it found no published system that combines agents, a scene graph, splats and JEPA; the nearest neighbours are x3d_mcp (validated X3D editing over MCP), SAGE and SimWorlds (planner, coder and reviewer agents with physics or deterministic verifiers), NuRec with Isaac Sim (splats in USD plus a simulator) and REALM (an MLLM agent that edits splats) ([x3d_mcp](https://github.com/Web3DConsortium/x3d_mcp); [SAGE](https://arxiv.org/html/2602.10116v2); [SimWorlds](https://arxiv.org/pdf/2607.01766); [NuRec](https://developer.nvidia.com/omniverse/nurec); [REALM](https://openaccess.thecvf.com/content/CVPR2026/papers/Shi_REALM_An_MLLM-Agent_Framework_for_Open_World_3D_Reasoning_Segmentation_CVPR_2026_paper.pdf)) [S/D]. The proposal also defines what "robust, productive, optimal" can mean without overclaiming: optimal is a measured trade-off among gate pass rate, visual fidelity at a device splat budget, credits per accepted world, loop latency and critic agreement with humans, not a global optimum (**Inference**).

### What AI-enabled X3D would look like

Picture an X3D 4.x scene whose splat worlds sit behind `Inline` nodes (GLB with `KHR_gaussian_splatting`, or SOG), whose Marble collider GLBs sit beside them as invisible shapes, and whose ROUTEs carry interactivity. Each subgraph has an owner agent with declared invariants recorded in node metadata; agents never write the file directly but submit patches to a transaction layer that validates, verifies, signs and commits them; and a planner turns goals into plans under a credit and rate budget. An illustrative loop (**Speculation**): a user asks for a mezzanine in a generated warehouse; the planner drafts a JSON plan; the splat curator requests a draft Marble world and runs the axis, scale and SH tests; the steward inserts an `Inline` and a `Transform`; the validator runs schema and splat-array rules; the physics checker drops test bodies on the collider; the verifier renders multi-view and normal-map views and consults a debiased VLM judge last; provenance signs the manifest; the commit lands or rolls back.

              x3d_mcp, X_ITE bridge, XSD / glTF-Validator, physics sim
            +---------+---------+----------+-----+----------------+

Four mechanisms make the agents "live inside" the graph rather than beside it. Ownership and invariants are recorded in node metadata (the `GaussianSplats` node carries a `metadata` field) ([X_ITE docs](https://github.com/create3000/x_ite/blob/main/docs/_posts/components/GaussianSplats/GaussianSplats.md)) [D], and an index graph mirrors the scene with every edge tagged authored or extracted versus agent-asserted, adapting the `EXTRACTED`/`INFERRED` convention of Graphify, which is a code and document graph rather than a 3D scene graph ([Graphify README](file:///home/user/graphify/README.md)) [D] (**Inference**). Querying that index as a graph database has precedent in an LLM writing Cypher against a Neo4j scene graph ([arXiv 2510.16643](https://arxiv.org/pdf/2510.16643)) [S], and layered object, place and room schemas from Hydra and ConceptGraphs suit the semantic layer ([Hydra](https://roboticsproceedings.org/rss18/p050.html); [ConceptGraphs](https://arxiv.org/pdf/2309.16650)) [S]. Semantics for splats would come from per-Gaussian instance IDs of the Gaussian Grouping and LangSplat families ([Gaussian Grouping](https://arxiv.org/pdf/2312.00732)) [S], but no source documents how those IDs become scene-graph nodes, so the curator must own that mapping (**Speculation**). Skill accrues as verified edit macros stored like Voyager's code skill library and SceneCraft's spatial skill library, admitted only after passing every gate ([Voyager](https://arxiv.org/html/2305.16291v2); [SceneCraft](https://arxiv.org/abs/2403.01248)) [S] (**Inference**); World Labs already ships agent skills in this style ([skills](https://github.com/worldlabsai/skills)) [D]. Agents are scoped to subgraphs, not nodes: no per-node LLM-agent pattern appears in the literature found, and its cost is unknown (**Inference**).

### Where a JEPA-style predictor fits and what data it needs

A JEPA is not a generator, so it cannot replace Marble; it can sit beside the agents as a critic or planner. Four seats are possible, ordered by how much evidence supports them.

| Seat | What it would do | Data needed | Evidence | Label |
|---|---|---|---|---|
| Critic of simulated outcomes | Predict the next latent given an action in a Marble-derived simulator; high prediction error ("surprise") flags implausible states | Many-camera splat renders with exact poses and depth; collider-based physics rollouts with action logs; labelled failures (floaters, wrong scale, interpenetration) and negative controls; camera diversity | LeWM surprise on implausible events [S]; depth from rasterization in GaussGym [S]; camera-position sensitivity in V-JEPA 2-AC [S] | Inference |
| Planner for embodied tasks in the generated world | Latent MPC by cross-entropy search toward a goal image, with a frozen encoder and an action-conditioned predictor | Action-labelled robot trajectories from the simulator, on the scale of tens of hours (V-JEPA 2-AC used under 62 hours of Droid) plus a pretrained encoder | V-JEPA 2-AC, DINO-WM [S] | Inference, Speculation |
| Planner for scene-graph edits | Treat edits as actions and score candidates by latent distance to a goal render | Edit logs with before and after renders and gate outcomes; none exist, so the system must generate its own | No published system; encoders can become action-insensitive when little of the frame responds to actions ([2610.03137](https://arxiv.org/html/2610.03137)) [S, title] | Speculation |
| Splat-native encoder | Embed segmented objects for retrieval and anomaly detection | Splat-token datasets at ShapeSplat scale | Gaussian-JEPA is object-level only [S] | Speculation |

Public starting points are small: V-JEPA 2 checkpoints and code at [facebookresearch/vjepa2](https://github.com/facebookresearch/vjepa2) [S], LeJEPA code at [rbalestr-lab/lejepa](https://github.com/rbalestr-lab/lejepa) [S] and H-JEPA's reported MIT code and checkpoints [T], while AMI Labs has no product and says its first applications are at least a year away [T]. **Inference:** the realistic prototype trains a LeWM- or DINO-WM-class model on the system's own renders and physics rollouts rather than waiting for a vendor model. Any JEPA critic must be benchmarked against two baselines, a physics-simulator check and a debiased VLM judge, on held-out defects, using the 0.66 kappa between two judge families reported in the related 2026 preprints ([2606.18451](https://arxiv.org/pdf/2606.18451); [2607.10826](https://arxiv.org/abs/2607.10826)) [S] only as a reference point for human-agreement targets (**Speculation** on the target).

### Risks

| Risk | Evidence | Mitigation | Label |
|---|---|---|---|
| **Unauthenticated arbitrary-code Blender MCP socket** | blender-mcp's own page warns that arbitrary code execution is dangerous and that the addon socket has no authentication or encryption; `execute_blender_code` runs Python in the live session ([repo](https://github.com/ahujasid/blender-mcp)) [D] | Never expose the port; typed allow-listed operations; token authentication; sandboxed headless Blender; no network egress; remove code execution in production; audit log | Grounded |
| Prompt injection through prompts, asset metadata and tool output | The agents consume text from many tools; no incident is documented in the notes | Treat all tool output as data; structured outputs; separate generator and judge models; human review of skills | Inference |
| Vendor continuity | AMD close pending; no word on Marble or API pricing, shutdown or migration; signed URLs expire; one article claims the terms allow ending the service ([BERI](https://www.beri.net/article/amd-world-labs-acquisition-marble-world-api-continuity-world-model-hardware-lock-in)) [T, unverified] | Adapter interface; local cache with hashes; avoid Atlas-only dependencies until documented | Grounded, Inference |
| Licensing and terms | Free tier is non-commercial; attribution on request; a training-on-user-content clause is unverified; INRIA reference software is non-commercial; add-ons are GPL ([Terms](https://docs.worldlabs.ai/terms-of-service); [INRIA licence](https://github.com/graphdeco-inria/gaussian-splatting/blob/main/LICENSE.md)) [T/D] | Written confirmation from World Labs; licence review of trainers and add-ons | Grounded |
| Standards drift | KHR text edited 13 Oct 2026; compression PRs open; SPZ v2 versus v4; X3D 4.1 is a draft with one implementer; SOG versus SOGS | Pin versions; sniff content, not extensions; conformance tests in CI | Grounded |
| Silent conversion errors | Axes, quaternion order, SH rotation, activation functions, Apply Transform gap (Tables 2 and 3) | Stage 0 and Stage 1 tests; normalise once | Grounded |
| Non-metric, coarse geometry | Arbitrary units, simplified colliders, splat-derived meshes with holes ([Mesh export](https://docs.worldlabs.ai/marble/export/mesh)) [S] | Apply `metric_scale_factor`; reference-object checks before physics | Grounded |
| Critic blind spots and circular validation | Splat renders hide mesh defects; VLM position bias; agents grading their own output | Layered gates, order swapping, normal-map views, human-labelled holdout, independent judge model | Grounded, Inference |
| JEPA critic failure modes | Action-insensitive encoders, domain gap, static scenes | Stage 4 gates; baselines; stop rule | Grounded (title level), Speculation |
| Scale and performance | Splat budgets of about 1M on Quest 3 and 1 to 5M on desktops; one-frame sort lag; inline X3D arrays reach 74 MB for 133k SH3 splats; x3d_mcp is immature ([Spark performance](https://github.com/sparkjsdev/spark/blob/main/docs/docs/performance.md)) [D] | LoD and SOG tiers; Inline references rather than inline arrays; subgraph-scoped agents | Grounded |
| Cost runaway | Three starts a minute, 60 an hour; about $1.20 per standard world and up to 3,080 credits for a text-prompted Plus world | Budget guard; draft model for iteration | Grounded, Inference |
| No provenance standard for 3D | No C2PA binding to glTF or USD found | Custom signed manifest; revisit when a standard appears | Inference |

Four observations would change this proposal: an asymmetric-marker test showing the two download channels differ in axes; Blender 5.3 slipping or gaining a splat exporter; AMD terms or Atlas altering Marble's endpoints; and Stage 4 showing no lift over the physics and VLM baselines, which would retire the JEPA seat while leaving the rest of the architecture intact.
