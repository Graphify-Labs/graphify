## 1. X3D + AI: Web3D Consortium activity, X3D validators, X_ITE, X3D 4.1 status, LLM-to-X3D generation

### Takeaway
There is real, current, Web3D-sanctioned work: an "AI with X3D" special interest group, a spec-grounded MCP server (`x3d_mcp`, accepted at Web3D 2026) that wraps layered X3D validation, and a 2024 ACM Web3D paper benchmarking LLMs at X3D generation. It is early (draft charter, draft X3D 4.1, no releases, small repo). The validator stack (XSD, Schematron, X3DJSAIL, X3DUOM, ontology) is mature and is exactly what an agent needs as a verification oracle. X3D has no gaussian-splat support in any ratified spec yet (a `GaussianSplats` node exists in the 4.1 draft only).

**x3d_mcp (the most directly relevant artifact)**
- `Web3DConsortium/x3d_mcp`: MCP server "for generating, validating, and converting X3D content (ISO/IEC 19775)", built with the AI with X3D SIG. README (direct): ~35 tools incl. workflow (`create_scene`, `create_geometry`, `compose_scene`), granular editing (`create_node`, `set_field`, `add_child`, `add_route`, `def_node`, `use_node`, `remove_node`, `get_scene`, `reset_scene`), validation (`validate_x3d`, `validate_current_scene`, `validate_semantic`, `autofix_x3d`), conversion (`convert_x3d`), query (`list_nodes`, `describe_node`, `list_components`, `list_profiles`), ontology query (`query_ontology`, `node_parents`, `describe_ontology_term`), rendering (`x3dom_page`, `render_image`, `render_current_scene`), scene manipulation/animation tools and guided prompts (`build_scene`, `audit_scene`, `animate_scene`). — [Web3DConsortium/x3d_mcp](https://github.com/Web3DConsortium/x3d_mcp) (direct)
- Validation is four layers per the README: (1) type checking at generation via `x3d.py`; (2) XSD validation with lxml against `x3d-4.1.xsd`; (3) JSON Schema validation (against the 4.0 JSON schema); (4) semantic checks in Python. X3DUOM is the data source (README says 267 concrete nodes). Schematron appears only in dependency notes, not in the four-layer pipeline. Encodings: XML `.x3d`, JSON `.x3dj`, ClassicVRML `.x3dv`. — [Web3DConsortium/x3d_mcp](https://github.com/Web3DConsortium/x3d_mcp) (direct)
- Maturity (direct): 6 stars, 6 forks, 65 commits, 14 open issues, 2 open PRs, no published releases/packages; targets X3D 4.1 which the README calls a "candidate draft"; Python 3.12+, uv, stdio by default and optional streamable-HTTP; optional Playwright rendering; BSD-style Web3D Consortium Open-Source License. — [Web3DConsortium/x3d_mcp](https://github.com/Web3DConsortium/x3d_mcp)
- README states the paper "x3d_mcp: A Model Context Protocol Server for AI-Assisted X3D Authoring" (Nikhil Narra, Rick Lentz, Nicholas Polys, Don Brutzman) was accepted to Web3D 2026 (13-15 Oct 2026, Doha). (direct) — [Web3DConsortium/x3d_mcp](https://github.com/Web3DConsortium/x3d_mcp)
- The original repo `ricklentz/x3d_mcp` was archived 4 May 2026 with the codebase migrated to the Web3D Consortium the same day (1 star, 18 commits at archive time). (direct) — [ricklentz/x3d_mcp](https://github.com/ricklentz/x3d_mcp)
- Web3D blog post dated 17 July 2026, "Specification-Grounded Authoring for a More Intelligent Web3D Ecosystem" (Anita Havele), argues raw LLM output is brittle (invented node names, broken ROUTEs) unless grounded in the authoritative spec; the MCP server supplies spec data for correct node names, field types, ROUTE validity and DEF/USE consistency. (search-summary) — [Web3D blog](https://www.web3d.org/blog/anitahavele/specification-grounded-authoring-more-intelligent-web3d-ecosystem); [x3dmcp page](https://www.web3d.org/pages/x3dmcp)

The current README (above) lists a JSON Schema layer, so this may have been addressed after the thread; not verified. (search-summary) — [x3d-public Apr 2026 (022494)](https://web3d.org/pipermail/x3d-public_web3d.org/2026-April/022494.html)
- Separate third-party `niknarra/x3d-mcp` (Glama listing) exposes `x3d_semantic_check` (Shape missing geometry/appearance, duplicate DEF names, invalid ROUTE refs) and `x3d_route` (checks DEF/field names and types before adding a ROUTE). Nikhil Narra is also a co-author on the Web3D paper, so this is plausibly a precursor, but that link is my inference. ### Inferences
- `x3d_mcp` already implements the "agent edits scene graph through tools, with validation in the loop" pattern for X3D; its tool list (DEF/USE, ROUTE, node-level CRUD, semantic validation, ontology query, render) is a direct template for scene-graph-resident agents. Its weakness is maturity (draft target spec, no releases, 14 open issues) and no splat or glTF-asset tools.
- The X3D validator stack (XSD + Schematron + X3DUOM + Tooltips + Ontology) is a richer deterministic oracle than glTF's, because X3D has ROUTE/event semantics to check; this is a differentiator for X3D as an agent substrate.
- Because X3D's `GaussianSplats` node exists only as a 4.1 draft/proposal while glTF and OpenUSD already have splat extensions/schemas, splat-in-X3D today most plausibly means glTF-`KHR_gaussian_splatting` content loaded through X3D's glTF import path (X_ITE loads glTF), not a native node. Speculative; no source confirms the path works.

- Could not open web3d.org primary pages, the x3d_mcp PDF, or the Web3D 2026 proceedings; the paper's evaluation results (if any) are unknown.
- No source found for X_ITE's Script node / ProtoDeclare/ExternProto behaviour or its SAI methods (create3000.github.io unreachable); the one 2020 list thread hinted Script support was a weakness in X3DOM/X_ITE, but I would not rely on it.
- No LLM X3D benchmark with quantitative validity rates found; no evidence found of Brutzman publishing "X3D + LLM" semantic-web papers beyond co-authoring the x3d_mcp paper (his X3D Ontology/Tooltips work is documented but not LLM-linked in what I saw).

- Brutzman's own X3D Ontology (RDF/OWL) is only evidenced via the x3d_mcp ontology-query tools; no standalone page read.

## 2. Scene-graph agents in the research literature (LLM scene generation/editing, robot 3D scene graphs, agentic 3D 2025-2026)

### Takeaway
Three generations are visible: (a) 2023-24 one-shot or constraint-solver LLM scene synthesis (3D-GPT, Holodeck, SceneCraft); (b) 2025 tool-using "agentic" generators with self-critique (SceneWeaver, spatially contextualized VLM agents); (c) 2026 systems with physics-simulator or deterministic verifiers in the loop, often driven over MCP (SAGE, SceneSmith, SimWorlds, WorldClaw, VibeWorlding). In robotics, hierarchical 3D scene graphs (Hydra, ConceptGraphs) are the established state representation that LLM planners read (SayPlan), and 2025-26 work puts scene graphs into graph databases that LLMs query with Cypher. All of it is research-grade; only a few have released code.

### Cited Findings

**LLM scene synthesis (2023-24)**
- Holodeck (Yang et al., CVPR 2024; arXiv 2312.09067): GPT-4 designs floor plan, materials, doors/windows, then selects among 50K+ Objaverse assets and places them with constraint-based optimization, built on AI2-THOR; annotators preferred it over manual procedural baselines in residential scenes; used to train navigation agents for scenes like music rooms and daycares. A follow-up "Holodeck 2.0" is arXiv 2508.05899. (search-summary) — [Holodeck, CVPR 2024](https://openaccess.thecvf.com/content/CVPR2024/papers/Yang_Holodeck_Language_Guided_Generation_of_3D_Embodied_AI_Environments_CVPR_2024_paper.pdf); [Holodeck 2.0](https://arxiv.org/html/2508.05899v1)
- SceneCraft (Hu et al., ICML 2024; arXiv 2403.01248): LLM agent writes Blender Python, uses a scene graph as a blueprint, converts spatial relations to numeric constraints, inner loop uses GPT-V render critique, outer loop grows a reusable "spatial skill library". Reported ablation: removing inner-loop visual refinement cuts the constraint score by 38.4 points (as relayed by a later paper). Code not released at the time of the paper. (search-summary) — [SceneCraft arXiv](https://arxiv.org/abs/2403.01248); [PMLR](https://proceedings.mlr.press/v235/hu24g.html)
- 3D-GPT (Sun et al., 3DV; arXiv 2310.12945): three agents (task dispatch, conceptualization, modeling) that deduce parameters and generate Python to drive Blender/Infinigen; a public implementation drives Infinigen with LLM-generated scripts and has no explicit license. (search-summary) — [3D-GPT arXiv](https://arxiv.org/pdf/2310.12945)
- Later comparisons (author-reported, not independent): Holodeck-style solvers give more physical plausibility but weaker fidelity to fine-grained spatial instructions; LayoutGPT often yields floating/mis-oriented objects; SceneCraft/Holodeck use coarse proximity rules; LayoutVLM-style differentiable optimization proposed as alternative. (search-summary) — [Direct Numerical Layout Generation (2506.05341)](https://arxiv.org/pdf/2506.05341); [SceneOrchestra (2604.19907)](https://arxiv.org/pdf/2604.19907)

**Agentic generators with verification (2025-26)**
- Agentic 3D Scene Generation with Spatially Contextualized VLMs (arXiv 2505.20129): four-stage pipeline with an auto-verification step where the model checks its own Blender code against spatial context. Survey "3D Scene Generation" is arXiv 2505.05474. (search-summary) — [2505.20129](https://arxiv.org/html/2505.20129v2); [survey](https://arxiv.org/pdf/2505.05474)
- SceneWeaver (NeurIPS 2025; arXiv 2509.20414): LLM planner selects among scene-generation tools and iterates via self-evaluation of physical plausibility, visual realism and semantic alignment; SAGE's authors criticize it as lacking simulator-in-the-loop verification and physical attributes. (search-summary) — [SceneWeaver](https://arxiv.org/html/2509.20414v2); [NeurIPS poster](https://neurips.cc/virtual/2025/poster/115278)
- SAGE (NVIDIA; arXiv 2602.10116): agent generating simulation-ready environments, orchestrating floor-plan/layout/text-to-3D generators over MCP, with two critics including a physics critic that runs in Isaac Sim (stability under gravity, collisions). (search-summary) — [SAGE](https://arxiv.org/html/2602.10116v2)
- SceneSmith (Pfaff et al., MIT/TRI; arXiv 2602.09153): staged VLM agents (layout, furniture, small objects); reported 3-6x more objects than prior methods, <2% inter-object collisions, 96% of objects stable under physics simulation. (search-summary) — [SceneSmith](https://arxiv.org/pdf/2602.09153)
- SceneMosaic (arXiv 2609.05594) user study (as reported by SceneMosaic authors): physical-plausibility ratings SceneSmith 4.16, SAGE 2.81, SceneMosaic 4.47; notes long optimization trajectories of SAGE/SceneSmith are expensive. (search-summary) — [SceneMosaic](https://arxiv.org/pdf/2609.05594)
- SimWorlds (arXiv 2607.01766, posted ~2 Jul 2026; CMU/Harvard/UC Merced): planner/coder/reviewer agents; planner writes structured JSON plans and never touches Blender; Blender 5.1 driven through an MCP server; reported to use claude-opus-4-7 for all roles; checks runtime state with a deterministic verifier over a layered scene protocol (not just rendered images); outputs an editable .blend; introduces 4DBuildBench; ~70-120 min per scene. No separate code release found. (search-summary) — [SimWorlds](https://arxiv.org/pdf/2607.01766); [alphaxiv](https://www.alphaxiv.org/abs/2607.01766)
- WorldClaw (Tencent Hunyuan; arXiv 2608.05248, early Aug 2026): coarse-to-fine agentic open-world generation: planning agents produce a spec (regions, terrain, assets, materials, spatial relations), build a height-field terrain, reconstruct editable textured meshes and recover placement; render-based agents refine contacts. Authors argue MLLM agents lack precise 3D spatial control. (search-summary) — [WorldClaw](https://arxiv.org/pdf/2608.05248)
- Other 2026 agentic/layout works surfaced: SceneOrchestra (2604.19907, full tool-call trajectory generation), HOG-Layout (2604.10772), RoomPlanner (2511.17048), VibeWorlding (2608.15265), MAGIC (2607.11594), SceneTerAct (2603.29798), RoboLayout (2603.05522), FlowScene (2603.19598). (search-summary; titles/IDs only) — [SceneOrchestra](https://arxiv.org/pdf/2604.19907); [VibeWorlding](https://arxiv.org/pdf/2608.15265); [FlowScene](https://arxiv.org/pdf/2603.19598)

**Robotics 3D scene graphs + LLMs**
- SayPlan (Rana et al., CoRL 2023, PMLR 229): LLM searches a condensed hierarchical 3D scene graph for task-relevant subgraphs, uses a classical path planner, and an iterative replanning loop with feedback from a scene-graph simulator; evaluated on up to 3 floors / 36 rooms / 140 assets on a mobile manipulator. (search-summary) — [SayPlan, PMLR](https://proceedings.mlr.press/v229/rana23a.html)
- ConceptGraphs (Gu et al., arXiv 2309.16650): open-vocabulary 3D scene graphs from fusing 2D foundation-model masks into 3D objects, captioning with VLMs and inferring relations with LLMs; code uses RGB-D plus SAM/LLaVA/Grounded-SAM and GradSLAM. (search-summary) — [ConceptGraphs](https://arxiv.org/pdf/2309.16650)
- Hydra (Hughes, Chang, Carlone, RSS 2022; arXiv 2201.13360): real-time layered 3D scene graph (geometry up to rooms/buildings), built incrementally from an ESDF with loop-closure correction by embedded deformation graphs. (search-summary) — [Hydra, RSS XVIII](https://roboticsproceedings.org/rss18/p050.html)
- "Structured Interfaces for Automated Reasoning with 3D Scene Graphs" (arXiv 2510.16643): LLM writes Cypher against a Neo4j database holding a 3D scene graph (GraphRAG-style tool), compared with serializing the graph as text; evaluated on instruction grounding and scene QA. — [2510.16643](https://arxiv.org/pdf/2510.16643) (search-summary)
- 3DGraphLLM (ICCV 2025, arXiv 2412.18450), FreeQ-Graph (2506.13629) and FOUND-IT (2605.25371, LLM agent builds query-specific scene graphs and checks absence of objects) round out LLM+scene-graph understanding work. (search-summary) — [3DGraphLLM](https://iccv.thecvf.com/virtual/2025/poster/2415); [FOUND-IT](https://arxiv.org/pdf/2605.25371)
- OpenUSD-based LLM editing: a pipeline that has an LLM pick placement target/surface and write an insertion script on USD scenes (GPT-4o, GPT-4o mini) appears in the Articulate3D / "From Scan to Action" line; IL3D (2510.12095) argues USD's text form is LLM-readable. (search-summary) — [From Scan to Action](https://arxiv.org/pdf/2507.17585); [IL3D](https://arxiv.org/pdf/2510.12095)

### Inferences
- The repeating architecture is: structured plan (often a scene graph or JSON spec) -> code/tool calls against an editable DCC or engine -> deterministic verifier + render-critique -> loop. SimWorlds and SAGE show this running over MCP, which is the same interface a scene-graph-resident X3D/USD agent would use.
- The strongest trend for a V&V-focused design is moving from "VLM looks at a render" (SceneCraft, SceneWeaver) to "simulator/solver checks state" (SAGE, SceneSmith, SimWorlds). The comparative numbers are author-reported on different benchmarks and are not directly comparable.
- Hydra/ConceptGraphs-style layered graphs (objects, places, rooms) are the natural schema for the semantic layer an agent attaches to splat-derived objects; the Neo4j/Cypher interface paper is the closest precedent to querying a scene as a graph database.

### Gaps
- LayoutGPT, Text2Room, GraphDreamer, CommonScenes, OpenScene, and Armeni et al.'s original 3D Scene Graph (ICCV 2019): no sources retrieved this session; not described here.
- Code availability/licensing for SAGE, SceneSmith, SimWorlds, WorldClaw not checked (paper pages unreachable). SceneCraft code was unreleased at paper time; current status unknown.
- No RDF/OWL scene-graph + LLM source found (only Neo4j/Cypher).
- I did not verify that arXiv IDs 2603-2610 listed from search results correspond exactly to the titles (IDs were taken from result URLs).

## 3. Tooling that makes scene graphs agent-accessible (MCP servers, USD agents, protocols, agent frameworks, graph DBs)

### Takeaway
MCP is now the de facto bridge between LLM agents and DCC/engine scene graphs: Blender (very popular), Unity, Unreal, three.js/Babylon, NVIDIA Omniverse/Kit/Isaac, X3D (Web3D's own), plus community Marble and USD servers. Most are thin "execute code + inspect scene + screenshot" bridges with weak safety (arbitrary Python, unauthenticated sockets). Typed, validating tool surfaces (x3d_mcp, NVIDIA USD Code MCP) are rarer. MCP and A2A are both under Linux Foundation governance with 2026 versions.

### Cited Findings

**Blender**
- `ahujasid/blender-mcp` (GitHub page title shows as "ahujasid/mcp-for-blender" when fetched, possibly a rename; I did not confirm): 32.0k stars, 2.9k forks, 250 commits, MIT; nine tools: `execute_blender_code` (arbitrary Python in the live Blender), `look` (viewport/camera/multi-angle/animation-strip views and renders), `get_scene_info`, `generate_3d`, `search_assets`/`import_asset` (Poly Haven, Sketchfab, Poly Pizza), `get_addon_status`, `disable_telemetry`, `record_trajectory_feedback`. Page warns that arbitrary-code execution is dangerous, that the addon socket server has no authentication or encryption (keep on localhost), and describes an optional safe mode that checks scripts before running. No releases listed. (direct) — [ahujasid/blender-mcp](https://github.com/ahujasid/blender-mcp)
- Search summaries of the README disagree on version (1.5.5 vs 1.8.0); the project says it has no official website. (search-summary) — [Glama README mirror](https://glama.ai/mcp/servers/@ahujasid/blender-mcp/blob/7636d13bded82eca58eb93c3f4cd8708dfdfbe8b/README.md)

## 4. Validation and verification of generated 3D content

### Takeaway
Format-level validators are mature and scriptable (glTF-Validator, X3D XSD/Schematron/Validator, usdchecker; NVIDIA's USD Validate is demo-only). The live frontier is semantic/physical V&V: simulator-in-the-loop checks (Isaac Sim), geometric gates (interpenetration, support, flood-fill reachability), and VLM judges, which recent studies show are biased and render-dependent. Provenance (C2PA) for 3D and determinism are essentially unaddressed in what I found.

### Cited Findings

**Format validators**
- Khronos glTF-Validator checks a glTF against the full spec and reports every error/warning/hint; CLI emits a JSON report and returns a non-zero exit code on errors; browser version runs locally; npm package exists. (search-summary) — [Vulkan docs: glTF-Validator](https://docs.vulkan.org/tutorial/latest/Advanced_glTF/Tooling_Production_Pipeline/03_validation.html); [glTF Validator](https://github.khronos.org/glTF-Validator); [npm](https://www.npmjs.com/package/gltf-validator)
- NVIDIA "USD Validate" model card: service for rule-based and visual validation of usdz files, "for demonstration purposes and not for production usage"; limits include unsupported UDIM tiles. A 2022 Khronos agenda notes USDZ validation is largely manual and asks whether to extend usdchecker or build a new tool. (search-summary) — [USD Validate model card](https://build.nvidia.com/nvidia/usdvalidate/modelcard); [ASWF wiki](https://wiki.aswf.io/x/F09yAg)
- X3D: XSD + Schematron + X3D Validator + (new) four-layer x3d_mcp pipeline; see section 1.

**Physical / geometric / reachability checks in generated scenes**
- SAGE: physics critic runs in Isaac Sim (gravity stability, collisions). SceneSmith: <2% collisions, 96% stable after physics sim. (search-summary) — [SAGE](https://arxiv.org/html/2602.10116v2); [SceneSmith](https://arxiv.org/pdf/2602.09153)
- RoomPlanner: valid only when bounding-box collision penalty (objects and walls) is zero; iterative adjustment with a 30 s cap. VibeWorlding: Python checks for interpenetration/clipping and height support (floating assets) plus a rubric-based LLM judge. MAGIC: flood-fill on a 2D occupancy grid to check portal reachability. SceneTerAct: agent-aware verification of navigability/reachability/clearance for given agent profiles (height, reach, locomotion), reused as an RL reward. RoboLayout: reachability constraints inside differentiable layout optimization. (search-summary) — [RoomPlanner](https://arxiv.org/pdf/2511.17048); [VibeWorlding](https://arxiv.org/pdf/2608.15265); [MAGIC](https://www.alphaxiv.org/abs/2607.11594v1); [SceneTerAct](https://arxiv.org/pdf/2603.29798); [RoboLayout](https://ui.adsabs.harvard.edu/abs/arXiv:2603.05522)
- A gamedev.net practitioner post describes first-pass Unity tests for AI-generated levels (goal reachability, collision, interaction), isolated for failure attribution. No paper found that uses an engine navmesh specifically as the validator. (search-summary) — [gamedev.net post](https://gamedev.net/blogs/entry/2298273-first-pass-tests-for-an-ai-generated-3d-level-in-unity-reachability-collisions-and-performance)
- Constraint solving: Holodeck's constraint optimization improves physical validity but can drift from the instruction (author-reported comparison, section 2).

**VLM / LLM-as-judge for 3D (2026 preprints, provisional)**
- 3D-DefectBench argues judge reliability depends on the whole pipeline (rendering, visual evidence, task spec, human reference labels): 84 inference configs, ~3.2M scored decisions, nine defect types. Two protocols query both presentation orders and keep only order-consistent verdicts because VLM judges fall back on position bias. Gaussian-splat renders can make broken meshes look clean (judge near chance); a four-view normal-map montage fixed that; adding reference plus a seven-image panel overwhelmed the judge. A cross-model protocol on a 24-view rig reports Cohen's kappa 0.66 between two judge families and finds geometry-validity statistics only weakly informative and render-CLIP at chance. (search-summary; the 3D-DefectBench arXiv ID is inferred from result grouping) — [2606.20364](https://arxiv.org/pdf/2606.20364); [2606.18451](https://arxiv.org/pdf/2606.18451); [2607.10826](https://arxiv.org/abs/2607.10826)

**Provenance, determinism, property-based testing**
- C2PA: no 3D-specific binding (glTF/USD) found in searches. An academic paper proposes SHA-256 hashing plus digital signatures for glTF integrity (independent of C2PA). (search-summary) — [C2PA spec 2.2](https://spec.c2pa.org/specifications/specifications/2.2/specs/C2PA_Specification); [glTF integrity paper (ITB)](https://informatika.stei.itb.ac.id/~rinaldi.munir/Kriptografi-dan-Koding/2025-2026/Makalah2026/Integrity%20Verification%20of%20GLTF%203D%20Models%20Using%20SHA-256%20Hashing%20and%20Digital%20Signatures.pdf)
- SimWorlds uses a "deterministic verifier" over a layered scene protocol but reports 70-120 min runtimes dominated by Blender bake time; it does not (in the summary) claim bit-reproducible scenes. (search-summary) — [SimWorlds](https://arxiv.org/pdf/2607.01766)

### Inferences
- The strongest published recipe is a layered gate: format validator -> geometric/physics checks -> task/semantic checks -> (last) VLM judge, with VLM verdicts debiased by order-swapping and rendered with defect-revealing views (normal maps, multi-view). That recipe is my synthesis of the cited papers, not one paper's design.
- Splat renders are a hazard for render-based critics (they hide mesh defects), which matters for any splat-in-the-loop design.
- Provenance for agent edits is an open space for 3D: C2PA has no 3D binding in the sources found, so signed edit logs would likely need a custom manifest (speculative).

### Gaps
- usdchecker itself (rules, CLI) was not documented from a primary source; only passing mentions.
- No source found for property-based testing of scenes, or for formal methods (SMT/CP-SAT) specifically applied to 3D scene layouts beyond Holodeck-style constraint optimization.
- No source on determinism of agentic scene edits or on scene-diff/regression tools.
- Search results for the C2PA topic were dominated by secondary guides; the official C2PA site's supported-asset-type list was not checked.

## 5. Agent-in-the-scene models (embodied agents, NPC agents, per-node/ECS/actor patterns)

### Takeaway
Embodied LLM agents in game-like worlds exist as research (Voyager, SIMA 2) and as commercial NPC stacks (Convai, Inworld, NVIDIA ACE) whose 2026 status is murky. Genie 3 is a closed world model with consumer-limited access via Project Genie; SIMA 2 agents trained partly inside Genie 3 worlds is the closest existing "agent plus world-model-generated environment" loop, but it is a limited research preview. I found no evidence of a "per-node agent" pattern (one agent per scene-graph node) in the literature.

### Cited Findings

A secondary source reports ~65% vs 31% task success vs SIMA 1 (not from DeepMind's blog). (search-summary) — [DeepMind SIMA 2](https://deepmind.google/blog/sima-2-an-agent-that-plays-reasons-and-learns-with-you-in-virtual-3d-worlds/); [InfoQ](https://www.infoq.com/news/2025/12/sima-2-gemini-agent)
- Genie 3: announced 5 Aug 2025 (text-to-navigable world, ~24 fps, 720p, minutes of consistency). Project Genie (research prototype on Genie 3) opened 29 Jan 2026 to US Google AI Ultra subscribers (18+), 60-second sessions; a May 2026 Street View feature was added; Waymo built a "Waymo World Model" on Genie 3. One outlet gives 23 June 2026 as an access date, conflicting with January. I found no public Genie 3 API. (search-summary) — [DeepMind Genie 3](https://deepmind.google/discover/blog/genie-3-a-new-frontier-for-world-models/); [Project Genie launch coverage](https://technews.tw/2026/01/30/google-rolls-out-project-genie-access-to-google-ai-ultra-subscribers-in-the-us/); [Genie (Wikipedia)](https://en.wikipedia.org/wiki/Genie_(world_model))
- NPC stacks: Convai = hosted NPC platform (dialogue, voice, memory, perception) for Unity/Unreal/three.js/web; Inworld described (July 2026 guide) as pivoting to B2B voice/agent infrastructure; NVIDIA ACE = Riva ASR, TTS, Audio2Face, and a claimed 2026 open-source ACE Game Agent SDK with UE5 plugins in beta, which I could not confirm from an NVIDIA primary source. Ubisoft Neo NPCs described as in-house research. (secondary guides only) — [Cinevva AI NPC guide 2026](https://app.cinevva.com/guides/ai-npcs-dialogue); [Inworld vs Convai vs ACE](https://tech-insider.org/inworld-ai-vs-convai-vs-nvidia-ace-2026/)
- REALM (CVPR 2026): an MLLM-agent framework for open-world 3D reasoning segmentation and editing inside 3DGS scenes (see section 6). (search-summary) — [REALM](https://openaccess.thecvf.com/content/CVPR2026/papers/Shi_REALM_An_MLLM-Agent_Framework_for_Open_World_3D_Reasoning_Segmentation_CVPR_2026_paper.pdf)

### Inferences
- Voyager's skill library (executable code retrieved by similarity) and SceneCraft's spatial-skill library are the same pattern; a scene-resident agent could persist "verified edit macros" this way. Inference.
- SIMA 2 + Genie 3 demonstrates the agent/world-model coupling as a closed Google system; nothing in sources suggests an open API for third-party agents to do the same.

### Gaps
- Generative Agents ("Smallville"), Unity ML-Agents, Unreal Mass/MetaHuman, ECS/actor-model/behavior-tree+LLM patterns: no sources retrieved; not described.
- No evidence found for per-node (per-entity) LLM agents in scene graphs; nothing on cost/latency scaling of per-node agents.
- NVIDIA ACE 2026 status unconfirmed from NVIDIA.

## 6. Splat interop with scene graphs; semantic decomposition of splats; world-model APIs; JEPA as critic/predictor

### Takeaway
Splats are now first-class in glTF (release candidate), OpenUSD (shipped in 26.03), Isaac Sim (GA in 6.0), and Blender (5.3, due Nov 2026, import/render only), with X3D only at draft. Semantic/instance decomposition of splats is an active research area (Gaussian Grouping, LangSplat, OpenGaussian, SAGA, AG2aussian, REALM). JEPA-style world models exist (V-JEPA 2-AC, many 2026 arXiv follow-ups, AMI Labs funded) but I found no published system using a JEPA predictor as a critic over scene-graph edits; that role is speculation.

### Cited Findings

**Splat as a scene-graph asset**

(search-summary) — [Khronos announcement](https://www.khronos.org/news/permalink/khronos-announces-gltf-gaussian-splatting-extension); [Radiance Fields: Khronos platform page](https://radiancefields.com/platforms/the-khronos-group); [Digital Production Feb 2026](https://digitalproduction.com/2026/02/04/gltf-learns-to-splat-without-losing-the-plot/)

**Semantic / instance decomposition and editing of splats**
- Gaussian Grouping (arXiv 2312.00732): per-Gaussian identity encoding supervised by SAM masks; supports removal, colorization, object position exchange without training and inpainting with minutes of fine-tuning; open-vocabulary inference requires rasterization plus Grounded-SAM and a predefined view. OpenGaussian: point-level understanding with SAM masks, CLIP embeddings, contrastive losses and a codebook. SAGA: promptable 3D segmentation extending SAM to Gaussians. AG2aussian (ICCV 2025): anchor-graph structured Gaussians for instance-level understanding and editing. SLAG (2505.08124), Gen-LangSplat (2510.22930). (search-summary; method descriptions come from a search tool's summary) — [Gaussian Grouping](https://arxiv.org/pdf/2312.00732); [AG2aussian](https://arxiv.org/pdf/2508.01740); [SLAG](https://arxiv.org/pdf/2505.08124); [Gen-LangSplat](https://arxiv.org/pdf/2510.22930)
- Language-agent editing of splats: REALM (CVPR 2026) MLLM-agent for reasoning segmentation/editing in 3DGS (removal, replacement, style); MLLMSplat (CVPR 2026 poster); OpenGS-Fusion (LLM front-end for object relocation/rotation/removal); LangDriveCTRL (2512.17445, scene graph with static background plus dynamic object nodes for driving-scene editing with multimodal agents). None found that combines LLM agent + explicit scene graph + splat object edits for general scenes. (search-summary) — [REALM](https://openaccess.thecvf.com/content/CVPR2026/papers/Shi_REALM_An_MLLM-Agent_Framework_for_Open_World_3D_Reasoning_Segmentation_CVPR_2026_paper.pdf); [MLLMSplat](https://cvpr.thecvf.com/virtual/2026/poster/38512); [LangDriveCTRL](https://arxiv.org/pdf/2512.17445)
- Feature-3DGS and SplatTalk: no sources retrieved (see Gaps).

**JEPA / world models**
- V-JEPA 2 (Meta, June 2025; arXiv 2506.09985): 1.2B-parameter video model; V-JEPA 2-AC (action-conditioned latent world model) post-trained on <62 hours of unlabeled Droid robot video, deployed zero-shot on Franka arms for pick-and-place with image goals; planning = minimize L1 distance between predicted future representation and goal representation ("energy") with the Cross-Entropy Method, execute first action, replan; checkpoints on Hugging Face. ### Inferences (speculation flagged)
- Established, source-backed: splats can now be carried as a typed node in glTF (RC), OpenUSD (shipped), Blender (5.3 point-cloud type), so an agent can attach semantics to a splat asset via the host format's own extension points. Instance decomposition methods produce per-Gaussian IDs/features that could populate object nodes; the bridge from those IDs to scene-graph nodes is not documented in any source I found.
- SPECULATION: V-JEPA 2-AC style planning (latent energy against a goal image, CEM over actions) could in principle score candidate agent edits if edits are expressed as actions on rendered or point-based observations; but V-JEPA 2-AC is trained on robot video and actions, not scene-graph edits, and the reported collapse failure mode (action-insensitive encoders) is a specific risk. No published system does this.
- SPECULATION: SR-JEPA (3D-native latent prediction, object-deletion evaluation) is the closest published substrate to a "scene-state predictor", but it is a representation-learning paper.
- Marble is a generator behind an async REST API with splat/mesh export, so in an agent loop it behaves like another generator tool (as in SAGE's generator orchestration), not a critic.

## 7. Existing projects that already combine agentic LLMs + 3D scene graphs + splats + JEPA/world models

### Takeaway
No project found combines all four. Partial overlaps exist: (LLM agent + MCP + validated scene editing) is well represented; (agent + physics-in-the-loop generation) is represented by SAGE; (splat + USD + simulator) by NVIDIA NuRec/Isaac Sim; (agent + world model) by SIMA 2 + Genie 3 (closed). The full stack, especially anything with JEPA or a scene graph over splats, appears to be unbuilt or at best a hobby/case-study.

### Inferences
- The combination "agent + scene graph + splat + JEPA" is a gap, not a crowded field. The nearest-neighbour builds are: SAGE/SimWorlds/x3d_mcp (agent + validated scene editing over MCP), NuRec/Isaac Sim (splat in USD + simulator), REALM (agent + splat editing), and V-JEPA 2-AC/SR-JEPA (latent predictors). The pieces that do not yet connect in published work are (a) splat object IDs -> scene-graph nodes, and (b) a JEPA-type latent predictor serving as an agent's critic.
- Any claim of prior art for the full stack should be treated with suspicion unless backed by a primary source; I found none.
