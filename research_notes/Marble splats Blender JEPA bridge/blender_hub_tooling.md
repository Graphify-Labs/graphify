## 1. Blender itself: native splat support, add-ons, editing, rendering, mesh<->splat, baking/training

### Takeaway
Blender 5.3 (scheduled stable release 10 Nov 2026; merged into main 16 Sep 2026) is the first Blender with *native* Gaussian-splat **import** (PLY, SPZ, USD) and **rendering** (Workbench/EEVEE/Cycles) but has **no splat export** and several documented rough edges (Apply Transform does not update splat attributes, sRGB-vs-linear mismatch, weak performance). The "hub" role therefore still depends on third-party add-ons for export, cleanup and SH-aware editing; the add-on ecosystem is fragmented, mostly small/GPL, with KIRI's "3DGS Render" the largest and most mature (moving to community maintenance).

### Cited Findings
**Native Blender 5.3**
- Blender main has commits "implements importing gaussian splats from PLY" (9f130c9, 16 Sep 2026), "makes the Import PLY node handle gaussian splats" (1bd98e9, 16 Sep 2026) and "sanitizes the SPZ and PLY importers against malformed files (GSplat)" (7cdcac1, 17 Sep 2026); Oct 20-21 2026 commits are PLY import robustness fixes (brechtvl, Aras Pranckevicius), i.e. the code is actively being hardened right now — [F] [blender/blender commits, io/ply](https://github.com/blender/blender/commits/main/source/blender/io/ply)
- Official 5.3 release notes (as summarised by search tool, page not opened): Workbench, EEVEE and Cycles all render splats; default splat shading is an emissive shader; a `radiance` attribute exposes resolved radiance at the shading point; relighting is "rudimentary" (swap emission for a hard-surface BSDF such as Diffuse). Three listed limitations: (1) performance "not ideal"; (2) splats assumed trained in sRGB while Cycles/EEVEE work in linear (visible in low-opacity/high-radiance areas); (3) **Apply Transform does not yet handle the new scale, rotation and spherical-harmonics attributes** — [S] [Blender 5.3 Rendering release notes](https://developer.blender.org/docs/release_notes/5.3/rendering/)
- Formats/architecture (secondary reports of the release notes): import from PLY and SPZ (SPZ up to v4, with automatic coordinate conversion; files written outside the SPZ convention may need manual rotation); splats stored as a Point Cloud with a new "3D Gaussian Splat" type; PLY importer auto-detects splat PLYs; new **Import SPZ** and **Set Point Cloud Type** geometry nodes; Import PLY node outputs a point cloud for splats and a mesh otherwise; USD import of the `UsdVolParticleField3DGaussianSplat` schema — [S] [DigitalProduction, 22 Sep 2026](https://digitalproduction.com/2026/09/22/blender-5-3-brings-gaussian-splats-home/); [S] [Cinevva news, 16 Sep 2026](https://app.cinevva.com/news/2026-09-16-blender-5-3-gaussian-splats); [S] [Neural4D import guide](https://blog.neural4d.com/user-guide/blender-gaussian-splatting/)
- **No export of splats in 5.3** (both PLY and SPZ); release scheduled 10 Nov 2026; alpha window reported as ending 30 Sep — [S] [Cinevva](https://app.cinevva.com/news/2026-09-16-blender-5-3-gaussian-splats); [S] [Radiance Fields](https://radiancefields.com/blender-5.3-will-bring-native-3d-gaussian-splat-import-and-rendering)
- Sources disagree on the merge story/count of limitations (one outlet says four limitations; official notes list three; one says design task opened June 2026 with PR #163102) — [S] search summaries of the above; I could not open projects.blender.org.
- Third-party add-ons are already building on the 5.3 attribute layout (`radiance:base` etc.): see Gaussian Splat Patch / splat-render below.

**Blender Foundation statements**
- The only Foundation-side statements I found are the 5.3 release notes (limitations; "no export") and the commit trail above. I found no roadmap/devtalk statement on export or on a splat file-format policy.

### Inferences
- For a Blender-centered "transmission point" the *import* leg is now first-class (and tracks the SPZ spec so Marble SPZ should import directly), but the *export* leg must go through add-ons: 3DGS Render (edited 3DGS PLY), Gaussian Splat Patch (INRIA PLY), or the user's own X3D exporter for scene-graph output. A native exporter would be the biggest single improvement to the hub idea; absence in 5.3 suggests it could come in 5.4+ (speculation).
- Because Apply Transform is documented as broken for splat attributes, any pipeline that bakes transforms in Blender before export risks corrupting scale/rotation/SH; prefer exporting with transforms intact (empties/parents) or use an add-on that rotates SH explicitly (3DGS Render bake, Patch Merge) or do the bake in splat-transform/SuperSplat.
- Blender 5.3 is moving fast through PLY/SPZ importer hardening, so add-ons built against the 5.3 alpha (Patch, splat-render) may need updating at release; treat them as experimental.

## 2. Unreal Engine 5.x

### Takeaway
Unreal has no first-party splat module (as of the sources I could read); the ecosystem is a set of third-party plugins of very uneven maintenance. World Labs' own guidance names Akiya (Fab), Volinga (paid), and VIVE Mars Nova (private beta) as the practical options, and says the older XVERSE and Luma plugins are not actively maintained. Splats are visual-only: collision and Lumen/Nanite integration are weak across the board.

### Cited Findings
- World Labs' Unreal guide/comparison covers three plugins: **Akiya "3D Gaussians Plugin"** (Fab, one-time purchase, one `.ply` at a time, dynamic lights/fog, shadow casting with perf cost and artifacts, DOF + nDisplay support); **VIVE Mars** (focus on runtime performance, PLY + SPZ, multiple splats per scene; *Nova 3DGS* in invite-only private beta, UE 5.4-5.6); **Volinga** (UE 5.3+, Windows only, paid, additive lighting, multiple splats per level; Plugin Pro adds proxy-mesh support/HDR workflow; 14-day watermarked non-commercial trial); World Labs recommends Volinga for DOF/virtual production — [S] [World Labs plugin comparison](https://www.worldlabs.ai/labs/learn/unreal-splat-plugins); [S] [World Labs Unreal export docs](https://docs.worldlabs.ai/marble/export/gaussian-splat/unreal)
- World Labs docs also state the XVerse and Luma plugins "are not actively maintained", XVerse is functional on UE5.2 with visual artefacts from aggressive downsampling, and shows texture errors importing PLY on UE 5.5 — [S] [World Labs Unreal export docs](https://docs.worldlabs.ai/marble/export/gaussian-splat/unreal) (secondary summary of the docs)
- Community tip in World Labs docs: switching the splat material from Translucent to Masked with AA Temporal Dither makes depth of field work, at slight quality cost — [S] [World Labs Unreal export docs](https://docs.worldlabs.ai/marble/export/gaussian-splat/unreal)
- **Akiya plugin** changelog: Lumen not supported; plugin can receive GI light but brightness may be unstable and it cannot emit GI; latest changelog entry seen v1.16 (Jan 2026); a Fab forum thread reports crashes importing .ply on UE 5.3-5.5 (undated, ~600 days old per search metadata) — [S] [Akiya changelog](https://akiya-research-institute.github.io/3dGaussiansPlugin-Manual/en/changelog/); [Fab listing](https://www.fab.com/listings/43088b82-e55a-4ea8-a453-f0774f10d5a2); [S] [Epic forum thread](https://forums.unrealengine.com/t/3d-gaussians-plugin-crashes-ue/2373986)
- **XV3DGS / XScene-UEPlugin (XVERSE)** — Apache-2.0, Niagara-based, imports .ply; README lists UE 5.1-5.3 (an aggregator says up to 5.5); an index lists last push **March 2024** => stale — [S] [XV3DGS mirror](https://github.com/zenkibomb/XV3DGS-UEPlugin); [S] [Radiance Fields: free UE5 plugin](https://radiancefields.com/free-unreal-engine-5-gaussian-splatting-plugin)

### Inferences
- The only plugin with demonstrated explicit Marble guidance is Akiya (PLY only => export PLY from Marble or convert SPZ->PLY). VIVE Mars/Volinga also read PLY; SPZ reading is claimed for VIVE Mars only.
- For a Blender->Unreal return path, the safest interchange is **PLY (INRIA layout)** written by an add-on (3DGS Render, Gaussian Splat Patch) rather than any glTF-based format, since I found no Unreal splat plugin that is verified to import KHR_gaussian_splatting except Cesium (3D Tiles route).
- Lumen/Nanite interplay is poor everywhere; plan on splats as a visual-only layer with separate collision proxy (GLB collider) and baked/cheat lighting.

## 3. Unity

### Takeaway
aras-p/UnityGaussianSplatting is still the best-known package (3.4k stars, MIT) but its main branch has had **no commits since 17 Oct 2025** and its author says no significant further development; for Unity 6 / URP / HDRP / Quest, newer forks and commercial packages (UnitySplats lineage, SplatBridge, Quest-specific forks) fill the gap. No Unity first-party splat solution was found.

### Cited Findings
- aras-p/UnityGaussianSplatting: 3.4k stars, 483 forks, MIT for viewer code (original 3DGS training code is non-commercial); built with Unity 2022.3; needs D3D12/Metal/Vulkan (DX11, OpenGL/GLES, WebGPU unsupported); reports Quest 3 and Quest Pro work, Apple Vision Pro "may not work", mobile unreliable/untested; imports INRIA PLY and Scaniverse SPZ into a compressed GaussianSplat asset; README: "not planning any significant further developments" (Dec 2023 status) — [F] [repo](https://github.com/aras-p/UnityGaussianSplatting)

- World Labs' Unity page: aras-p plugin works on Unity 6.1 but main branch has draw-order issues with multiple splats and problems importing Marble SPZ; **2M-splat SPZ works, 500K SPZ throws index-out-of-range => convert to PLY first** — [S] [World Labs Unity export docs](https://docs.worldlabs.ai/marble/export/gaussian-splat/unity)

## 4. Web: three.js, Babylon.js, PlayCanvas/SuperSplat, glTF KHR_gaussian_splatting, SPZ, SOG

### Takeaway
`KHR_gaussian_splatting` is now **ratified** (registry shows it under "Ratified Khronos Extensions"; README status "Complete, Ratified"), so GLB is a legitimate cross-engine container, but the **SPZ compression child extension (`KHR_gaussian_splatting_compression_spz_2`) is still an open PR**. In practice delivery today runs on PLY/SPZ/SOG: Spark (three.js, MIT, very active) for three.js, Babylon.js 9.x (native splats + a KHR_gaussian_splatting loader file), and PlayCanvas (SOG, streamed LOD, SuperSplat, splat-transform). Blender cannot export any of these natively; the bridge is Blender-add-on PLY -> splat-transform.

### Cited Findings
**glTF / SPZ / SOG standards**

## 5. X3D / X_ITE

### Takeaway

## 7. Practical conversion recipes: coordinates, units, SH rotation, cropping, LOD, compression, collision proxies, baking/retraining, relighting limits

### Takeaway
The recurring failure modes are (1) axis/handedness mismatches (RUB vs RDF vs LUF vs Blender Z-up), (2) quaternion component order (PLY w,x,y,z vs glTF/X3D x,y,z,w), (3) SH not rotated with the splat, (4) Apply Transform in Blender 5.3 not touching scale/rotation/SH, and (5) PLY's raw (log-scale/logit-opacity) encoding vs glTF's linear encoding. Use tools that explicitly rotate SH, and do cleanup/LOD/compression in splat-transform/SuperSplat rather than hand-rolled scripts.

### Cited Findings
- **Coordinate systems**: SPZ default is RUB (OpenGL/three.js); PLY typically RDF; GLB typically LUF; Unity RUF — [F] [nianticlabs/spz](https://github.com/nianticlabs/spz). Blender 5.3 converts SPZ automatically but files outside convention may need rotation — [S] [DigitalProduction](https://digitalproduction.com/2026/09/22/blender-5-3-brings-gaussian-splats-home/). Houdini and Nuke imports often arrive in a neutral orientation needing a rotation — [S] [Radiance Fields engine support](https://radiancefields.com/3d-gaussian-splatting-engine-support)
- **Marble conventions**: World Labs release notes say worlds now export in OpenGL rather than OpenCV for both splats and meshes (date conflicts: Dec 2025 vs Jan 2026); a DigitalProduction piece says default worlds use OpenCV and that correcting for DCC apps means negating Y and Z leaving X unchanged; exports use real-world unit scaling; API exposes per-world scale/ground-plane fields (`semantics_metadata`) and a splat-scale formula for SPZ in third-party engines (formula not seen) — [S] [Marble release notes](https://docs.worldlabs.ai/marble/release-notes), [S] [DigitalProduction](https://digitalproduction.com/2026/06/04/image-blaster-turns-images-into-splats/), [S] [World Labs API quickstart](https://docs.worldlabs.ai/api), [S] [invideo](https://invideo.io/blog/world-labs-marble-3d-worlds/)
- **glTF rule**: positions, quaternions and SH must all be rotated when loading data from another coordinate system; SH should also be rotated by node rotation — [F] [KHR README](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_gaussian_splatting/README.md)
- **Quaternion order**: glTF/X_ITE use x,y,z,w; feeding w,x,y,z data produces streaks in X_ITE — [F] [X_ITE doc](https://github.com/create3000/x_ite/blob/main/docs/_posts/components/GaussianSplats/GaussianSplats.md), [F] [x3d-blender-io](https://github.com/hagopjay/x3d-blender-io)
- **Scale/unit**: glTF `SCALE` is linear spread; x3d-blender-io stores `splat_scale` linear per axis and multiplies by unit factor on import — [F] [KHR README](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_gaussian_splatting/README.md), [F] [PR #12](https://github.com/hagopjay/x3d-blender-io/pull/12). blender-splat-render requires Blender unit scale set to real scene size for correct DOF — [F] [repo](https://github.com/timfennell/blender-splat-render)
- **SH rotation handling by tool**: Blender 5.3 Apply Transform does not update SH [S]; KIRI 3DGS Render: GPU-accelerated SH rotation during baking (5.1.0) [F]; Gaussian Splat Patch: rotates SH bands 1-3 on Clone/Merge [F]; Unity aras-p world-space export rotates SH [S]; PlayCanvas: SuperSplat SH rotation only on PLY export (docs/forum conflict) [S]; splat-transform: not stated [F]; KHR spec says SH should be rotated [F]. Sources: [Blender notes](https://developer.blender.org/docs/release_notes/5.3/rendering/), [KIRI releases](https://github.com/Kiri-Innovation/3dgs-render-blender-addon/releases), [Patch](https://github.com/timfennell/blender-splat-patch), [aras-p docs](https://deepwiki.com/aras-p/UnityGaussianSplatting), [PlayCanvas forum](https://forum.playcanvas.com/t/solved-sh-coordinates-and-gaussian-reorientation/40396), [splat-transform](https://github.com/playcanvas/splat-transform)
- **SH degree handling**: KHR and X_ITE treat a partial SH degree as absent; x3d-blender-io emits whole degrees only; SuperSplat 3.6.0 exports a chosen SH band count zero-padded; splat-transform can strip SH bands — [F] [PR #12](https://github.com/hagopjay/x3d-blender-io/pull/12), [F] [SuperSplat releases](https://github.com/playcanvas/supersplat/releases), [F] [splat-transform](https://github.com/playcanvas/splat-transform)
- **Cropping/cleanup**: splat-transform (box/sphere crop, opacity/scale filters, floater removal, cluster isolation, decimation) [F] [repo](https://github.com/playcanvas/splat-transform); Blender-side selection/crop in 3DGS Render and erase/heal in Gaussian Splat Patch [F]; Houdini GSOPs Reduce [F]
- **LOD**: Spark 2.0 LOD system (14 Apr 2026) [F]; PlayCanvas streamed SOG with default 512K Gaussians/chunk and distance-based LOD, SuperSplat requires LODs when publishing >40M splats [F]; Babylon coarse-first streaming [F]; Unreal NanoGS hierarchical LOD [S][V]; UnitySplats has none [F]. Sources: [Spark releases](https://github.com/sparkjsdev/spark/releases), [splat-transform](https://github.com/playcanvas/splat-transform), [SuperSplat releases](https://github.com/playcanvas/supersplat/releases), [Babylon releases](https://github.com/BabylonJS/Babylon.js/releases), [CG Channel NanoGS](https://www.cgchannel.com/2026/03/free-plugin-nanogs-puts-nanite-style-gaussian-splatting-in-unreal-engine/), [UnitySplats](https://github.com/icosa-mirror/UnitySplats)
- **Compression**: SPZ ~10x smaller than PLY (Niantic claim) [F]; SOG 15-20x (third-party claim) [S]; Marble 500K tier is the real-time tier, 2M full-res — [F] [spz](https://github.com/nianticlabs/spz); [S] [PlayCanvas manual](https://developer.playcanvas.com/user-manual/supersplat/editor/import-export/); [S] [invideo](https://invideo.io/blog/world-labs-marble-3d-worlds/)
- **Collision / mesh proxies**: Marble collider GLB is for physics, low-fidelity; Standard plan includes it; high-quality visual mesh is a separate (paid) option and independent testing found Marble mesh quality poor; NVIDIA workflow imports collider aligned with splat; GSOPs bake to mesh/volumes; SplatBridge advertises splat colliders; KIRI/Blender mesh shadow proxies — [S] [Marble mesh docs](https://docs.worldlabs.ai/marble/export/mesh), [S] [design4real test](https://design4real.de/en/world-labs-marble-practical-test/), [S] [NVIDIA blog](https://developer.nvidia.com/blog/simulate-robotic-environments-faster-with-nvidia-isaac-sim-and-world-labs-marble/), [F] [GSOPs](https://github.com/cgnomads/GSOPs), [S] [SplatBridge](https://radiancefields.com/splatbridge-brings-streamed-gaussian-splats-and-splat-colliders-to-unity-6)
- **Baking / re-training round trip**: Blender->COLMAP via Gauss Cannon (for LichtFeld/Brush/Postshot) and Gaussian-Render-Capture; BlenderNeRF for NGP/NeRF/3DGS datasets; mesh-to-splat via PLAN8VR exporter or KIRI's mesh-to-3DGS — [F] [Gauss Cannon](https://github.com/warpgatelabs/gauss-cannon), [F] [BlenderNeRF](https://github.com/maximeraafat/BlenderNeRF), [F] [PLAN8VR](https://github.com/PLAN8VR/blender-splat-exporter)
- **Relighting limits**: glTF spec: splats are display-referred (not affected by scene lighting/exposure/tonemapping), though implementations may relight; Blender 5.3 relighting "rudimentary" (swap emission for BSDF), sRGB/linear mismatch; true SH-based relight/self-shadow exists in blender-splat-render (early) and engine plugins (Volinga Pro, WallGS Pro, Akiya partial); GSOPs Relight IBL — [F] [KHR README](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_gaussian_splatting/README.md), [S] [Blender notes](https://developer.blender.org/docs/release_notes/5.3/rendering/), [F] [splat-render](https://github.com/timfennell/blender-splat-render), [F] [GSOPs](https://github.com/cgnomads/GSOPs)

### Inferences
- Suggested hub recipe (synthesis, not a tested workflow): Marble PLY (or SPZ) -> Blender 5.3 native import -> cleanup/crop/align (native point-cloud + geometry nodes, or Gaussian Splat Patch/3DGS Render) keeping transforms on parent empties (avoid Apply Transform) -> export edited PLY via add-on -> `splat-transform` (rotate to target frame with SH handling checked, crop, filter, LOD, SOG/GLB/SPZ) -> engine plugin/viewer. Keep Marble's collider GLB in the Blender scene as a separate object for alignment and physics proxy; export it as GLB/FBX alongside.

## 8. World Labs Marble export -> Blender (and Unreal / Unity): what the community and docs actually show

### Takeaway
Official docs exist for Marble -> Unreal and Unity (with concrete caveats), NVIDIA published Marble -> Isaac Sim, and secondary sources say World Labs also has Blender/Houdini guides, but I could not locate or open an official **Marble -> Blender** page, nor any Reddit/YouTube tutorial specifically for "Marble to Blender". The only Marble-specific GitHub tooling I found is generation (MCP servers/ComfyUI), not export. With Blender 5.3's native SPZ/PLY import, the Blender step is likely straightforward but undocumented by the community so far.

### Cited Findings
- Marble exports: Gaussian splats as `.spz` or `.ply` at ~2M or ~500K splat tiers, collider mesh (GLB), and higher-quality meshes; paid plan needed (Standard covers splat exports, 360 panoramas and collider meshes; Free generates only); one source says a high-quality mesh export costs ~$2.80 (unverified) — [S] [World Labs export index](https://docs.worldlabs.ai/marble/export/gaussian-splat/index), [S] [invideo](https://invideo.io/blog/world-labs-marble-3d-worlds/), [S] [Marble mesh export docs](https://docs.worldlabs.ai/marble/export/mesh)
- A secondary source states World Labs maintains official export guides for Blender, Unreal, Unity and Houdini; I could confirm only the Unreal and Unity pages exist (docs URLs below) — [S] [invideo](https://invideo.io/blog/world-labs-marble-3d-worlds/); [S] [Unreal guide](https://docs.worldlabs.ai/marble/export/gaussian-splat/unreal); [S] [Unity guide](https://docs.worldlabs.ai/marble/export/gaussian-splat/unity)

### Inferences
- What people practically do (inferred from docs and tool landscape): download PLY (or SPZ) + collider GLB; for Blender 5.3, drag in PLY/SPZ and keep the collider as hidden alignment/physics proxy; for older Blender, use 3DGS Render (PLY only); for engines, use PLY for Unreal (Akiya) and 2M-SPZ/PLY for Unity; for web use Spark; for robotics use 3DGRUT->USD ParticleField.
