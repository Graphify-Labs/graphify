模块由四个职责清晰的子文件组成，依赖方向单向向外（仅被 __main__、serve、watch 等上层调用）：
- `cli.py`：所有非 install 子命令的分发器，通过 `dispatch_command(cmd)` 按子命令名分支并延迟 import 具体实现（如 `graphify.query` → `serve._query_graph_text`），避免与 `__main__` 形成循环；内置 `_run_hook_guard` 作为 shell 钩子拦截 grep/read 工具调用并输出 PreToolUse nudge。
- `build.py`：图构建核心。`build_from_json` 负责 schema 规范化（links→edges、source→source_file、file_type 同义词映射、hyperedge members→nodes）、语义 ID 重映射（_semantic_id_remap 把旧短 stem 对齐到新全路径 stem）、AST vs LLM ghost 节点合并、跨语言 phantom edge 过滤（基于 _EDGE_LANG_FAMILY）、以及方向保留（_src/_tgt）。`build_merge` 在此基础上做增量替换（按 source_file 剔除旧贡献）与 prune_sources 删除，并复用现有 hyperedges。`deduplicate_by_label` 与 `graph_has_legacy_ids` 是辅助诊断/兼容函数。
- `global_graph.py`：用户家目录 `~/.graphify/global-graph.json` + `global-manifest.json` 的全局多仓库聚合图，通过 `prefix_graph_for_global` / `prune_repo_from_graph`（来自 build.py）对每个 repo 的节点 ID 加前缀隔离，并按 label 去重外部库节点。
- `storage.py`：可选的 NeuG 并行存储后端，单表 schema（node + edge），通过 CSV + COPY FROM 批量写入，支持全量 `_bulk_ingest` 与增量 `_incremental_ingest`（先保存跨文件入边再 DELETE affected source_files，最后恢复）。`execute_cypher` 暴露给 `cli.py` 的 `cypher` 子命令。

边界约定：NetworkX 图以 JSON node-link 格式在磁盘持久化（兼容 links/edges 双键），NeuG 仅在安装时可用（ImportError 由调用方捕获），所有用户输入经 `graphify.security.check_graph_file_size_cap` 校验后再解析。
