模块由三个职责正交的文件组成：
- `graphify/llm.py`：集中式 LLM 后端注册表 `BACKENDS`（dict[str, dict]），每个后端以配置项（base_url/default_model/env_key/pricing/vision 等）声明式描述；通过 `_call_openai_compat`、`_call_anthropic`、`_call_bedrock`、`_call_claude_cli`、`_call_azure` 等分支函数实现具体调用，统一封装图片 base64/base-path 投递、system prompt 注入、JSON 响应解析与注入哨兵防御（`<untrusted_source>` + 零宽字符 defang）。自定义提供者通过 `~/.graphify/providers.json` 或项目级 `.graphify/providers.json`（需显式 `GRAPHIFY_ALLOW_LOCAL_PROVIDERS=1`）动态合并入 BACKENDS。
- `graphify/hooks.py`：纯 Python 生成 shell 脚本并写入 `.git/hooks/post-commit` / `post-checkout`，使用 `# graphify-hook-start/end` 标记做幂等安装/卸载；通过 `_PYTHON_DETECT` 三段探针（pinned sys.executable → `graphify-out/.graphify_python` → PATH launcher shebang → python3/python）定位隔离 venv 中的解释器，并以跨平台 `_LAUNCHER_TEMPLATE` 启动后台重建进程，避免阻塞 git 钩子；同时注册 `merge.graphify` 驱动到 `git config` 并在 `.gitattributes` 中绑定 `graph.json merge=graphify`。
- `graphify/prs.py`：独立 CLI 子命令，通过 `gh` CLI 拉取 PR 列表、CI rollup、review 状态，结合本地 `graph.json` 计算受影响的社区与节点数（`compute_pr_impact`），支持 `--triage` 复用 `llm.BACKENDS` 选择 Opus/kimi/openai/gemini/claude-cli/ollama 进行优先级排序，`--conflicts` 输出共享社区的 PR 冲突组。
依赖方向：`prs.py` 反向 import `graphify.llm` 复用后端发现逻辑；`hooks.py` 仅依赖标准库与 subprocess/git，不引入 LLM SDK，保证钩子冷启动极快。
