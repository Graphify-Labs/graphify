- 顶层 `graphify/__init__.py` 通过 `__getattr__` 懒加载将 `extract/build/cluster/analyze/report/export/wiki/reflect` 等函数暴露为包级 API，使 `import graphify` 不触发重型依赖。
- `cli.py` 是命令分发中枢：解析子命令后调用对应模块（如 `graphify extract` → `graphify.extract`），并统一注入 `_run_hook_guard`、大小限制、计时器等横切逻辑。
- 提取阶段由 `graphify/extract.py` 作为门面，内部再委托给 `graphify/extractors/` 下的各语言 extractor；`extractors/__init__.py` 维护 `LANGUAGE_EXTRACTORS` 注册表，新增语言只需在此登记即可被分发。
- 构建阶段 `build.py` 把节点/边 dict 合并成 NetworkX 图，并通过 `_EDGE_LANG_FAMILY` 做跨语言 phantom-edge 过滤，同时承担路径归一化、超边成员别名折叠等跨子模块共享的数据契约。
- 导出阶段 `exporters/` 提供 Neo4j/FalkorDB 与 vis.js HTML 两种后端，被 `graphify.export` 门面统一调用。
- 技能文档 `skills/*/references/*.md` 与 `always_on/` 提示词构成外部 agent 的调用契约，与 CLI 子命令一一对应，形成「CLI 能力 ↔ 智能体参考文档」的双向映射。
- LLM/Git Hook/PR 工具 (`llm_backends_integrations`) 通过读取 `graphify-out/graph.json` 与上述流水线产物交互，构成对核心运行时的上层消费方。
