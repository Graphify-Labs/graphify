在你的 AI 编程助手中输入 `/graphify`，它会把你的整个项目（代码、文档、PDF、图片、视频）映射成一张**知识图谱**，让你可以**用查询取代在文件里逐个 grep**。

- **代码映射免费，完全本地运行。** 代码通过 tree-sitter AST 解析：确定性强、无需 LLM，任何内容都不会离开你的机器。（文档、PDF、图片和视频会使用你助手的模型或配置好的 API 密钥进行一次语义解析。）
- **每条边都有解释。** 每个连接都会被标记为 `EXTRACTED`（源文件中显式存在）或 `INFERRED`（由 graphify 推断得出），因此你能分清哪些是直接读取的、哪些是推断出来的。
- **这不是向量索引。** 没有嵌入、没有向量库：这是一张你可以真正遍历的图。提出一个问题、追踪两个事物之间的路径，或解释某一个概念。

<p align="center">

图谱构建完成后，你可以查询它而不必再逐个读文件。下面是在上述 FastAPI 代码库上运行 graphify 的真实输出：

```text
$ graphify explain "APIRouter"
Node: APIRouter
  Source:    routing.py L2210
  Community: 2
  Degree:    47

Connections (47):
  --> RequestValidationError [uses] [INFERRED]
  --> Dependant [uses] [INFERRED]
  --> .get() [method] [EXTRACTED]
  <-- __init__.py [imports] [EXTRACTED]
  ...

$ graphify path "FastAPI" "ModelField"
Shortest path (3 hops):
  FastAPI --uses--> DefaultPlaceholder <--references-- get_request_handler() --references--> ModelField
```

每条边都带有一个**置信度标签**（`EXTRACTED` = 源文件中显式存在，`INFERRED` = 由解析推导得出），因此你能分清哪些是直接读取的、哪些是推断出来的。`graphify query "<question>"` 会针对一个自然语言问题返回一个限定范围的子图，`graphify path A B` 则会追踪任意两个事物之间如何连接。

## 它能做什么

开箱即用你能获得的内容：

| 能力 | 你能获得什么 |
|---|---|
| **上帝节点（God nodes）** | 连接最多的概念，让你看清一切都汇聚于何处 |
| **社区（Communities）** | 将图谱拆分为子系统（Leiden），并带有无需 LLM 的标签 |
| **跨文件链接** | 通过 tree-sitter AST，在约 40 种语言中解析 `calls` / `imports` / `inherits` / `mixes_in` |
| **查询、路径、解释** | 提出问题、追踪两个事物之间的路径，或解释某一个概念，全部基于 `graph.json` |
| **理由 + 文档引用** | `# NOTE:` / `# WHY:` 注释以及 ADR/RFC 引用会成为与代码相连的一等节点 |
| **超越代码** | 文档、PDF、图片、视频/音频都会映射到同一张图中 |
| **本地优先** | 代码在本地用 tree-sitter 解析（无需 LLM，任何内容都不离开你的机器）；只有对文档/媒体的语义解析才会调用后端，而且仅在你配置后才会调用 |

## Install

> [!IMPORTANT]
> **官方软件包：** PyPI 上的软件包名为 `graphifyy`（双 y）。PyPI 上其他 `graphify*` 软件包与本项目无任何关联。CLI 命令仍为 `graphify`。

官方源码仓库是 [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify)。

**第 1 步 —— 安装软件包：**

```bash
# Recommended (isolated env; if 'graphify' isn't found after, run: uv tool update-shell):
uv tool install graphifyy

# Alternatives:
pipx install graphifyy
pip install graphifyy  # may need PATH setup — see note below
```

**第 2 步 —— 向你的 AI 助手注册该技能：**

```bash
graphify install
```

就这样。打开你的 AI 助手并输入 `/graphify .`

若要将助手技能安装到当前仓库而非你的用户
配置目录，请加上 `--project`：

```bash
graphify install --project
graphify install --project --platform codex
```

项目范围的安装会写入当前目录之下，例如
`.claude/skills/graphify/SKILL.md` 或 `.agents/skills/graphify/SKILL.md`（外加一个
技能按需加载的 `references/` 附带目录），并会
为可提交的文件打印一条 `git add` 提示。
支持项目范围安装的各平台命令都接受相同的参数，
例如 `graphify claude install --project` 或 `graphify codex install --project`。

> [!TIP]
> 遇到 `command not found`、Mac/Windows 上的 `pip` 问题、PowerShell 引号问题、`uvx` 用法、git 钩子的 PATH 怪癖，或是严格模式问题？请参阅 **[Installation](https://docs.graphify.com/installation)** 和 **[Troubleshooting](https://docs.graphify.com/troubleshooting)**。

## 让你的助手始终使用图谱

构建图谱后，在你的项目中运行一次：

在你的项目中运行一次 `graphify <platform> install`，例如 `graphify claude install` 或 `graphify codex install`（或 `graphify install --platform <name>`）。

这会写入一个小型配置文件，告诉你的助手在回答代码库问题时去查阅知识图谱，并优先使用像 `graphify query "<question>"` 这样的限定范围查询，而不是读取完整报告或对原始文件进行 grep。

- **钩子平台**（Claude Code、Gemini CLI）：在搜索类工具调用之前（以及在 Claude Code 上，通过 Read/Glob 工具逐个读取源文件之前）会自动触发一个钩子，推动你的助手走图谱这条路径。
- **指令文件平台**（Codex、OpenCode、Cursor 等）：持久化的指令文件（`AGENTS.md`、`.cursor/rules/` 等）提供同样的"查询优先"指引。

`GRAPH_REPORT.md` 仍可用于宽泛的架构评审。

**CodeBuddy** 做与 Claude Code 相同的两件事：写入一个 `CODEBUDDY.md` 段落，告诉 CodeBuddy 在回答架构问题前先读取 `graphify-out/GRAPH_REPORT.md`；并安装 `PreToolUse` 钩子（`.codebuddy/settings.json`），它会在 Bash 搜索命令和文件读取之前触发，推动改用 `graphify query`。

**Codex** 会写入 `AGENTS.md`，这正是该平台上真正承载始终在线图谱指引的地方。`graphify codex install` 也会在 `.codex/hooks.json` 中注册一个 `PreToolUse` 钩子（`graphify hook-check`），但该条目被刻意设为**空操作**：Codex Desktop 会拒绝 `PreToolUse` 上的 `hookSpecificOutput.additionalContext`，因此在那里发出提示会破坏 Bash 工具调用。与 Claude Code 不同——在 Claude Code 上由钩子（`graphify hook-guard`）负责提示——在 Codex 上，钩子会触发并刻意什么都不做，而 `AGENTS.md` 才是始终在线的机制。

**Kilo Code** 会将 Graphify 技能安装到 `~/.config/kilo/skills/graphify/SKILL.md`，并将一个原生的 `/graphify` 命令安装到 `~/.config/kilo/command/graphify.md`。`graphify kilo install` 还会写入 `AGENTS.md`，外加一个原生的 `tool.execute.before` 插件（`.kilo/plugins/graphify.js` + `.kilo/kilo.json` 或 `.kilo/kilo.jsonc` 注册），使 Kilo 能通过原生 `.kilo` 配置获得同样的始终在线图谱提醒行为。

**Cursor** 会写入 `.cursor/rules/graphify.mdc` 并设置 `alwaysApply: true`，因此 Cursor 会在每次对话中自动包含它，无需钩子。

要一次性从所有平台移除 graphify：`graphify uninstall`（加上 `--purge` 还会删除 `graphify-out/`）。或使用各平台对应的命令（例如 `graphify claude uninstall`）。

## 常用命令

```bash
/graphify .                        # build graph for current folder
/graphify ./docs --update          # re-extract only changed files
/graphify . --cluster-only         # rerun clustering without re-extracting
/graphify . --cluster-only --resolution 1.5      # more granular communities
/graphify . --cluster-only --exclude-hubs 99     # suppress utility super-hubs from god-node rankings
/graphify . --no-viz               # skip the HTML, just the report + JSON
/graphify . --wiki                 # build a markdown wiki from the graph
graphify export callflow-html      # Mermaid architecture/call-flow HTML (auto-regenerates on every git commit if hook is installed)

/graphify query "what connects auth to the database?"
/graphify path "UserService" "DatabasePool"
/graphify explain "RateLimiter"

/graphify add https://arxiv.org/abs/1706.03762   # fetch a paper and add it
/graphify add <youtube-url>                       # transcribe and add a video

graphify hook install              # auto-rebuild on commit + branch checkout (run `graphify update .` after `git pull` — see "Recommended workflow" below)
graphify merge-graphs a.json b.json              # combine two graphs

graphify prs                       # PR dashboard: CI state, review status, worktree mapping
graphify prs 42                    # deep dive on PR #42 with graph impact
graphify prs --triage              # AI ranks your review queue (uses whatever backend is configured)
graphify prs --conflicts           # PRs sharing graph communities — merge-order risk
```

参见下方的[完整命令参考](#full-command-reference)。

## 隐私

- **代码文件** —— 通过 tree-sitter 在本地处理。任何内容都不会离开你的机器。纯代码语料无需 API 密钥 —— `graphify extract` 完全离线运行。在混合仓库中，加上 `--code-only` 可仅索引代码，并跳过那些原本需要 LLM 的文档/PDF/图片。
- **视频 / 音频** —— 使用 faster-whisper 在本地转录。任何内容都不会离开你的机器。
- **文档、PDF、图片** —— 发送到你的 AI 助手进行语义提取（通过 `/graphify` 技能，使用你 IDE 会话所运行的任何模型）。无头的 `graphify extract` 需要 `GEMINI_API_KEY` / `GOOGLE_API_KEY`（Gemini）、`MOONSHOT_API_KEY`（Kimi）、`ANTHROPIC_API_KEY`（Claude）、`OPENAI_API_KEY`（OpenAI）、`DEEPSEEK_API_KEY`（DeepSeek）、一个正在运行的 Ollama 实例（`OLLAMA_BASE_URL`）、通过标准提供方链提供的 AWS 凭据（Bedrock —— 无需 API 密钥，使用 IAM），或者 `claude` CLI 二进制文件（Claude Code —— 无需 API 密钥，使用你的 Claude 订阅）。`--dedup-llm` 标志使用相同的密钥。
- **数据驻留** —— `graphify extract` 会根据已设置的 API 密钥自动检测使用哪个提供方（优先级：Gemini → Kimi → Claude → OpenAI → DeepSeek → Azure → Bedrock → Ollama）。对于有数据驻留要求的代码，请使用 `--backend ollama`（完全本地）或传入显式的 `--backend` 标志。Kimi（`MOONSHOT_API_KEY`）会路由到位于中国的 Moonshot AI 服务器。
- **无遥测**、无使用情况追踪、无分析。
- **查询日志** —— 每一次 `graphify query`、`graphify path`、`graphify explain` 以及 MCP `query_graph` 调用都会以 JSON Lines 格式记录到 `~/.cache/graphify-queries.log`（时间戳、问题、语料、返回的节点数、耗时）。默认**不**存储完整的子图响应。设置 `GRAPHIFY_QUERY_LOG_DISABLE=1` 可退出，或设置 `GRAPHIFY_QUERY_LOG=/dev/null` 在不禁用代码路径的情况下静默它。

## Graphify Cloud

[**Graphify Cloud**](https://app.graphify.com/login) 是构建在 graphify 之上的始终在线层。它不是一张你按文件夹按需重建的图，而是在你的整个软件开发生命周期中保持一张实时图：

- **token 减少 80%** —— 始终在线的记忆意味着你的智能体不必在每次会话中重新读取和重新解释代码库。
- **Monorepo 与跨仓库** —— 一张跨越每个服务和仓库的连通图，而不是每个文件夹一张图。
- **形式化验证** —— 对照实时图检查架构与依赖的不变式。
- **带有 SDLC 全局视角的代码评审** —— 在合并之前就看清一处改动如何波及整个系统。
- **SDLC 连接器** —— 接入 Sentry、Jira 等，让事故、工单和代码同处一张图中。
- **始终在线** —— 在后台跨代码、文档和会议持续更新。
