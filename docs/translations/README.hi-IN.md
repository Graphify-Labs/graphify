अपने AI कोडिंग असिस्टेंट में `/graphify` टाइप करें और यह आपके पूरे प्रोजेक्ट (कोड, डॉक्स, PDF, इमेज, वीडियो) को एक **नॉलेज ग्राफ** में मैप कर देता है, जिसे आप फाइलों में **grep करने के बजाय query** कर सकते हैं।

- **कोड मैप मुफ्त में, पूरी तरह लोकल।** कोड को tree-sitter AST से पार्स किया जाता है: डिटरमिनिस्टिक, कोई LLM नहीं, कुछ भी आपकी मशीन से बाहर नहीं जाता। (डॉक्स, PDF, इमेज और वीडियो के लिए सिमैंटिक पास हेतु आपके असिस्टेंट का मॉडल या कॉन्फ़िगर की गई API की का उपयोग होता है।)
- **हर एज की व्याख्या होती है।** हर कनेक्शन को `EXTRACTED` (स्रोत में स्पष्ट) या `INFERRED` (graphify द्वारा सुलझाया गया) के रूप में टैग किया जाता है, ताकि आप बता सकें कि क्या सीधे पढ़ा गया और क्या अनुमानित किया गया।
- **यह वेक्टर इंडेक्स नहीं है।** कोई embeddings नहीं, कोई वेक्टर स्टोर नहीं: एक असली ग्राफ जिसमें आप ट्रैवर्स करते हैं। कोई सवाल पूछें, दो चीज़ों के बीच का रास्ता ट्रेस करें, या किसी एक अवधारणा की व्याख्या कराएं।

**शुरू करें** (30 सेकंड):

```bash
uv tool install graphifyy      # install the CLI (or: pipx install graphifyy)
graphify install               # register the skill with your AI assistant
```

फिर, अपने AI असिस्टेंट में:

```
/graphify .
```

बस इतना ही। आपको **तीन फाइलें** मिलती हैं:

```
graphify-out/
├── graph.html       open in any browser — click nodes, filter, search
├── GRAPH_REPORT.md  the highlights: key concepts, surprising connections, suggested questions
└── graph.json       the full graph — query it anytime without re-reading your files
```

सहेजे गए ग्राफ में `graph.schema_version` शामिल होता है ताकि इंटीग्रेशन असंगत
फॉर्मेट बदलावों का पता लगा सकें, साथ ही `graph.graphify_version` जो इसे बनाने वाले
Graphify रिलीज़ की पहचान करता है।

**यहां काम करता है:** Claude Code, Cursor, Codex, Gemini CLI, GitHub Copilot, और 15+ और भी — [अपना प्लेटफॉर्म चुनें](#install)।

## इसे काम करते देखें

<p align="center">
  <img src="https://raw.githubusercontent.com/Graphify-Labs/graphify/v8/docs/demo-path.svg" alt="graphify path query: a terminal asks for the shortest path between FastAPI and ModelField, and the answer lights up hop by hop across the knowledge graph" width="900">
</p>

एक बार ग्राफ बन जाने पर आप फाइलें पढ़ने के बजाय उसे query करते हैं। असली आउटपुट, ऊपर दिखाए गए FastAPI कोडबेस पर चलाया गया graphify:

```text
$ graphify explain "APIRouter"
Node: APIRouter
  Source:    routing.py L2210
  Community: 2
  Degree:    47

Connections (47):
  --> RequestValidationError [uses] [INFERRED]
  --> Dependant [uses] [INFERRED]
  --> .get() [method] [EXTRACTED]
  <-- __init__.py [imports] [EXTRACTED]
  ...

$ graphify path "FastAPI" "ModelField"
Shortest path (3 hops):
  FastAPI --uses--> DefaultPlaceholder <--references-- get_request_handler() --references--> ModelField
```

हर एज एक **confidence tag** रखती है (`EXTRACTED` = स्रोत में स्पष्ट, `INFERRED` = resolution द्वारा निकाला गया), ताकि आप बता सकें कि क्या सीधे पढ़ा गया और क्या अनुमानित किया गया। `graphify query "<question>"` किसी सहज-भाषा के सवाल के लिए एक scoped subgraph लौटाता है, और `graphify path A B` ट्रेस करता है कि कोई दो चीज़ें कैसे जुड़ती हैं।

## यह क्या करता है

आपको बॉक्स से बाहर क्या मिलता है:

| क्षमता | आपको क्या मिलता है |
|---|---|
| **God nodes** | सबसे अधिक जुड़ी अवधारणाएं, ताकि आप देख सकें कि सब कुछ किसके माध्यम से प्रवाहित होता है |
| **Communities** | ग्राफ को सबसिस्टम में विभाजित किया गया (Leiden), LLM-मुक्त लेबल के साथ |
| **Cross-file links** | `calls` / `imports` / `inherits` / `mixes_in` जो tree-sitter AST के ज़रिए ~40 भाषाओं में सुलझाए जाते हैं |
| **Query, path, explain** | कोई सवाल पूछें, दो चीज़ों के बीच का रास्ता ट्रेस करें, या किसी एक अवधारणा की व्याख्या कराएं, सब कुछ `graph.json` के विरुद्ध |
| **Rationale + doc refs** | `# NOTE:` / `# WHY:` टिप्पणियां और ADR/RFC उद्धरण कोड से जुड़े फर्स्ट-क्लास नोड बन जाते हैं |
| **Beyond code** | डॉक्स, PDF, इमेज, और वीडियो/ऑडियो सभी एक ही ग्राफ में मैप होते हैं |
| **Local-first** | कोड tree-sitter के साथ लोकली पार्स होता है (कोई LLM नहीं, कुछ भी आपकी मशीन से बाहर नहीं जाता); केवल डॉक्स/मीडिया पर सिमैंटिक पास किसी बैकएंड को कॉल करता है, और वह भी तभी जब आप एक कॉन्फ़िगर करें |

> [!TIP]
> इसे कई रेपो या मोनोरेपो में चला रहे हैं? [Graphify Cloud](https://app.graphify.com/login) इसे लगातार करता है और एजेंट टोकन खर्च को 80% तक घटाता है, क्रॉस-रेपो लिंक, SDLC-व्यापी कोड रिव्यू, औपचारिक सत्यापन, और Sentry/Jira कनेक्टर्स के साथ। [14-दिन का मुफ्त ट्रायल शुरू करें &rarr;](https://app.graphify.com/login)

## Install

> [!IMPORTANT]
> **आधिकारिक पैकेज:** PyPI पैकेज `graphifyy` है (डबल-y)। PyPI पर अन्य `graphify*` पैकेज संबद्ध नहीं हैं। CLI कमांड अब भी `graphify` है।

आधिकारिक स्रोत रिपॉज़िटरी [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify) है।

**स्टेप 1 — पैकेज इंस्टॉल करें:**

```bash
# Recommended (isolated env; if 'graphify' isn't found after, run: uv tool update-shell):
uv tool install graphifyy

# Alternatives:
pipx install graphifyy
pip install graphifyy  # may need PATH setup — see note below
```

**स्टेप 2 — अपने AI असिस्टेंट के साथ स्किल रजिस्टर करें:**

```bash
graphify install
```

बस इतना ही। अपना AI असिस्टेंट खोलें और टाइप करें `/graphify .`

अपनी यूज़र प्रोफ़ाइल के बजाय मौजूदा रिपॉज़िटरी में असिस्टेंट स्किल इंस्टॉल करने के लिए,
`--project` जोड़ें:

```bash
graphify install --project
graphify install --project --platform codex
```

प्रोजेक्ट-स्कोप्ड इंस्टॉल मौजूदा डायरेक्टरी के नीचे लिखते हैं, उदाहरण के लिए
`.claude/skills/graphify/SKILL.md` या `.agents/skills/graphify/SKILL.md` (साथ ही एक
`references/` साइडकार जिसे स्किल मांग पर लोड करती है), और
कमिट की जा सकने वाली फाइलों के लिए `git add` संकेत प्रिंट करते हैं।
प्रोजेक्ट-स्कोप्ड इंस्टॉल का समर्थन करने वाली प्रति-प्लेटफॉर्म कमांड वही फ्लैग स्वीकार करती हैं,
उदाहरण के लिए `graphify claude install --project` या `graphify codex install --project`।

> [!TIP]
> `command not found`, Mac/Windows पर `pip` की समस्या, PowerShell कोटिंग, `uvx` उपयोग, git-hook PATH की दिक्कतें, या strict मोड से टकरा रहे हैं? देखें **[Installation](https://docs.graphify.com/installation)** और **[Troubleshooting](https://docs.graphify.com/troubleshooting)**।

## अपने असिस्टेंट को हमेशा ग्राफ उपयोग करने के लिए सेट करें

ग्राफ बनाने के बाद अपने प्रोजेक्ट में इसे एक बार चलाएं:

अपने प्रोजेक्ट में `graphify <platform> install` एक बार चलाएं, उदाहरण के लिए `graphify claude install` या `graphify codex install` (या `graphify install --platform <name>`)।

यह एक छोटी कॉन्फ़िग फाइल लिखता है जो आपके असिस्टेंट को बताती है कि कोडबेस के सवालों के लिए नॉलेज ग्राफ से सलाह ले, पूरी रिपोर्ट पढ़ने या कच्ची फाइलें grep करने के बजाय `graphify query "<question>"` जैसी scoped query को प्राथमिकता दे।

- **Hook प्लेटफॉर्म** (Claude Code, Gemini CLI): सर्च-शैली के tool कॉल से पहले (और Claude Code पर, Read/Glob tools के ज़रिए स्रोत फाइलों को एक-एक करके पढ़ने से पहले) एक hook अपने आप चलता है और आपके असिस्टेंट को ग्राफ पथ की ओर प्रेरित करता है।
- **Instruction-file प्लेटफॉर्म** (Codex, OpenCode, Cursor, आदि): स्थायी इंस्ट्रक्शन फाइलें (`AGENTS.md`, `.cursor/rules/`, आदि) वही query-first मार्गदर्शन प्रदान करती हैं।

`GRAPH_REPORT.md` व्यापक आर्किटेक्चर समीक्षा के लिए अब भी उपलब्ध है।

**CodeBuddy** वही दो काम करता है जो Claude Code करता है: एक `CODEBUDDY.md` सेक्शन लिखता है जो CodeBuddy को आर्किटेक्चर सवालों के उत्तर देने से पहले `graphify-out/GRAPH_REPORT.md` पढ़ने को कहता है, और `PreToolUse` hooks (`.codebuddy/settings.json`) इंस्टॉल करता है जो Bash सर्च कमांड और फाइल रीड से पहले चलते हैं, और इसके बजाय `graphify query` की ओर प्रेरित करते हैं।

**Codex** `AGENTS.md` में लिखता है, जो इस प्लेटफॉर्म पर वास्तव में हमेशा-चालू ग्राफ मार्गदर्शन वहन करता है। `graphify codex install` `.codex/hooks.json` में एक `PreToolUse` hook (`graphify hook-check`) भी रजिस्टर करता है, लेकिन वह प्रविष्टि जानबूझकर एक **no-op** है: Codex Desktop `PreToolUse` पर `hookSpecificOutput.additionalContext` को अस्वीकार करता है, इसलिए वहां nudge उत्सर्जित करना Bash tool कॉल को तोड़ देगा। Claude Code के विपरीत, जहां hook (`graphify hook-guard`) nudging करता है, Codex पर hook चलता है और जानबूझकर कुछ नहीं करता, और `AGENTS.md` ही हमेशा-चालू तंत्र है।

**Kilo Code** Graphify स्किल को `~/.config/kilo/skills/graphify/SKILL.md` और एक नेटिव `/graphify` कमांड को `~/.config/kilo/command/graphify.md` पर इंस्टॉल करता है। `graphify kilo install` `AGENTS.md` के साथ एक नेटिव `tool.execute.before` प्लगइन (`.kilo/plugins/graphify.js` + `.kilo/kilo.json` या `.kilo/kilo.jsonc` रजिस्ट्रेशन) भी लिखता है ताकि Kilo को नेटिव `.kilo` कॉन्फ़िग के ज़रिए वही हमेशा-चालू ग्राफ रिमाइंडर व्यवहार मिले।

**Cursor** `.cursor/rules/graphify.mdc` को `alwaysApply: true` के साथ लिखता है, ताकि Cursor उसे हर बातचीत में अपने आप शामिल करे, किसी hook की ज़रूरत नहीं।

सभी प्लेटफॉर्म से graphify को एक साथ हटाने के लिए: `graphify uninstall` (`graphify-out/` को भी हटाने के लिए `--purge` जोड़ें)। या प्रति-प्लेटफॉर्म कमांड उपयोग करें (उदा. `graphify claude uninstall`)।

## सामान्य कमांड

```bash
/graphify .                        # build graph for current folder
/graphify ./docs --update          # re-extract only changed files
/graphify . --cluster-only         # rerun clustering without re-extracting
/graphify . --cluster-only --resolution 1.5      # more granular communities
/graphify . --cluster-only --exclude-hubs 99     # suppress utility super-hubs from god-node rankings
/graphify . --no-viz               # skip the HTML, just the report + JSON
/graphify . --wiki                 # build a markdown wiki from the graph
graphify export callflow-html      # Mermaid architecture/call-flow HTML (auto-regenerates on every git commit if hook is installed)

/graphify query "what connects auth to the database?"
/graphify path "UserService" "DatabasePool"
/graphify explain "RateLimiter"

/graphify add https://arxiv.org/abs/1706.03762   # fetch a paper and add it
/graphify add <youtube-url>                       # transcribe and add a video

graphify hook install              # auto-rebuild on commit + branch checkout (run `graphify update .` after `git pull` — see "Recommended workflow" below)
graphify merge-graphs a.json b.json              # combine two graphs

graphify prs                       # PR dashboard: CI state, review status, worktree mapping
graphify prs 42                    # deep dive on PR #42 with graph impact
graphify prs --triage              # AI ranks your review queue (uses whatever backend is configured)
graphify prs --conflicts           # PRs sharing graph communities — merge-order risk
```

## गोपनीयता

- **कोड फाइलें** — tree-sitter के ज़रिए लोकली प्रोसेस होती हैं। कुछ भी आपकी मशीन से बाहर नहीं जाता। केवल-कोड वाले corpus के लिए किसी API की की ज़रूरत नहीं — `graphify extract` पूरी तरह ऑफ़लाइन चलता है। मिश्रित रेपो पर, केवल कोड को इंडेक्स करने और उन डॉक्स/PDF/इमेज को छोड़ने के लिए जिन्हें अन्यथा LLM की ज़रूरत होती, `--code-only` जोड़ें।
- **वीडियो / ऑडियो** — faster-whisper के साथ लोकली ट्रांसक्राइब होते हैं। कुछ भी आपकी मशीन से बाहर नहीं जाता।
- **डॉक्स, PDF, इमेज** — सिमैंटिक एक्सट्रैक्शन के लिए आपके AI असिस्टेंट को भेजे जाते हैं (`/graphify` स्किल के ज़रिए, आपके IDE सेशन में जो भी मॉडल चलता है उसका उपयोग करके)। हेडलेस `graphify extract` के लिए `GEMINI_API_KEY` / `GOOGLE_API_KEY` (Gemini), `MOONSHOT_API_KEY` (Kimi), `ANTHROPIC_API_KEY` (Claude), `OPENAI_API_KEY` (OpenAI), `DEEPSEEK_API_KEY` (DeepSeek), एक चालू Ollama इंस्टेंस (`OLLAMA_BASE_URL`), मानक provider chain के ज़रिए AWS क्रेडेंशियल (Bedrock - कोई API की की ज़रूरत नहीं, IAM उपयोग करता है), या `claude` CLI बाइनरी (Claude Code - कोई API की की ज़रूरत नहीं, आपकी Claude सदस्यता उपयोग करता है) चाहिए। `--dedup-llm` फ्लैग वही की उपयोग करता है।
- **Data residency** — `graphify extract` अपने आप पता लगाता है कि कौन-सा provider उपयोग करना है, इस आधार पर कि कौन-सी API की सेट है (प्राथमिकता: Gemini → Kimi → Claude → OpenAI → DeepSeek → Azure → Bedrock → Ollama)। data-residency आवश्यकताओं वाले कोड के लिए, `--backend ollama` (पूरी तरह लोकल) उपयोग करें या एक स्पष्ट `--backend` फ्लैग पास करें। Kimi (`MOONSHOT_API_KEY`) चीन में Moonshot AI सर्वर पर रूट करता है।
- **कोई telemetry नहीं**, कोई उपयोग ट्रैकिंग नहीं, कोई analytics नहीं।
- **Query logging** — हर `graphify query`, `graphify path`, `graphify explain`, और MCP `query_graph` कॉल को `~/.cache/graphify-queries.log` में JSON Lines फॉर्मेट में लॉग किया जाता है (timestamp, question, corpus, लौटाए गए nodes, duration)। पूर्ण subgraph उत्तर डिफ़ॉल्ट रूप से संग्रहीत **नहीं** किए जाते। ऑप्ट-आउट करने के लिए `GRAPHIFY_QUERY_LOG_DISABLE=1` सेट करें, या कोड पथ को निष्क्रिय किए बिना चुप करने के लिए `GRAPHIFY_QUERY_LOG=/dev/null`।

## Graphify Cloud

[**Graphify Cloud**](https://app.graphify.com/login) graphify के ऊपर बना हमेशा-चालू स्तर है। प्रति फ़ोल्डर मांग पर दोबारा बनाए जाने वाले ग्राफ के बजाय, यह आपके पूरे सॉफ़्टवेयर डेवलपमेंट लाइफ़साइकल में एक लाइव ग्राफ बनाए रखता है:

- **80% कम टोकन** — हमेशा-चालू मेमोरी का मतलब है कि आपके एजेंट्स हर सेशन में कोडबेस को दोबारा पढ़ना और दोबारा समझाना बंद कर देते हैं।
- **मोनोरेपो और क्रॉस-रेपो** — हर सर्विस और रिपॉज़िटरी में एक जुड़ा हुआ ग्राफ, प्रति फ़ोल्डर एक ग्राफ नहीं।
- **औपचारिक सत्यापन** — आर्किटेक्चरल और dependency invariants को लाइव ग्राफ के विरुद्ध जांचें।
- **आपके SDLC के विहंगम दृश्य के साथ कोड रिव्यू** — मर्ज करने से पहले देखें कि कोई बदलाव पूरे सिस्टम में कैसे फैलता है।
- **SDLC कनेक्टर्स** — Sentry, Jira, और अन्य को खींच लें, ताकि इंसिडेंट, टिकट, और कोड एक ही ग्राफ में रहें।
- **हमेशा-चालू** — कोड, डॉक्स, और मीटिंग्स में बैकग्राउंड में लगातार अपडेट होता है।

**[app.graphify.com पर 14-दिन का मुफ्त ट्रायल शुरू करें &rarr;](https://app.graphify.com/login)**

## graphify पर निर्माण

graphify पारिस्थितिकी तंत्र में कुछ बना रहे हैं? यह प्रोत्साहित किया जाता है। यदि आपका प्रोजेक्ट अपने नाम में "graphify" उपयोग करता है (उदाहरण के लिए `graphify-dashboard` या `graphify-action`), तो कृपया अपने README में एक छोटा नोट जोड़ें जो स्पष्ट करे कि यह समुदाय-निर्मित है और Graphify Labs से संबद्ध या इसके द्वारा समर्थित नहीं है। "graphify" और graphify लोगो Graphify Labs के मार्क हैं; कृपया इन्हें इस तरह उपयोग न करें जिससे आधिकारिक दर्जे का संकेत मिले।
