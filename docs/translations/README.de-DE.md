Geben Sie `/graphify` in Ihrem KI-Programmierassistenten ein, und er bildet Ihr gesamtes Projekt (Code, Dokumente, PDFs, Bilder, Videos) als **Wissensgraph** ab, den Sie **abfragen können, statt mit grep** durch Dateien zu suchen.

- **Code-Mapping kostenlos, vollständig lokal.** Code wird mit dem tree-sitter-AST geparst: deterministisch, ohne LLM, nichts verlässt Ihren Rechner. (Für Dokumente, PDFs, Bilder und Video wird das Modell Ihres Assistenten oder ein konfigurierter API-Schlüssel für einen semantischen Durchlauf genutzt.)
- **Jede Kante wird erklärt.** Jede Verbindung ist mit `EXTRACTED` (explizit in der Quelle) oder `INFERRED` (von graphify aufgelöst) markiert, sodass Sie unterscheiden können, was direkt gelesen und was abgeleitet wurde.
- **Kein Vektorindex.** Keine Embeddings, kein Vektorspeicher: ein echter Graph, den Sie durchlaufen. Stellen Sie eine Frage, verfolgen Sie den Pfad zwischen zwei Dingen oder lassen Sie sich ein Konzept erklären.

## See it in action

<p align="center">
  <img src="https://raw.githubusercontent.com/Graphify-Labs/graphify/v8/docs/demo-path.svg" alt="graphify path query: a terminal asks for the shortest path between FastAPI and ModelField, and the answer lights up hop by hop across the knowledge graph" width="900">
</p>

Sobald der Graph erstellt ist, fragen Sie ihn ab, statt Dateien zu lesen. Echte Ausgabe, graphify ausgeführt auf der oben gezeigten FastAPI-Codebasis:

```text
$ graphify explain "APIRouter"
Node: APIRouter
  Source:    routing.py L2210
  Community: 2
  Degree:    47

Connections (47):
  --> RequestValidationError [uses] [INFERRED]
  --> Dependant [uses] [INFERRED]
  --> .get() [method] [EXTRACTED]
  <-- __init__.py [imports] [EXTRACTED]
  ...

$ graphify path "FastAPI" "ModelField"
Shortest path (3 hops):
  FastAPI --uses--> DefaultPlaceholder <--references-- get_request_handler() --references--> ModelField
```

Jede Kante trägt ein **Konfidenz-Tag** (`EXTRACTED` = explizit in der Quelle, `INFERRED` = durch Auflösung abgeleitet), sodass Sie unterscheiden können, was direkt gelesen und was abgeleitet wurde. `graphify query "<question>"` liefert einen eingegrenzten Teilgraphen für eine Frage in natürlicher Sprache, und `graphify path A B` verfolgt, wie zwei beliebige Dinge zusammenhängen.

## What it does

Was Sie von Haus aus erhalten:

| Fähigkeit | Was Sie erhalten |
|---|---|
| **God nodes** | Die am stärksten vernetzten Konzepte, damit Sie sehen, worüber alles fließt |
| **Communities** | Der Graph aufgeteilt in Teilsysteme (Leiden), mit LLM-freien Labels |
| **Dateiübergreifende Verknüpfungen** | `calls` / `imports` / `inherits` / `mixes_in` über ~40 Sprachen hinweg via tree-sitter-AST aufgelöst |
| **Query, path, explain** | Stellen Sie eine Frage, verfolgen Sie den Pfad zwischen zwei Dingen oder erklären Sie ein Konzept, alles gegen `graph.json` |
| **Begründung + Dok-Referenzen** | `# NOTE:`- / `# WHY:`-Kommentare und ADR/RFC-Zitate werden zu erstklassigen Knoten, die mit dem Code verknüpft sind |
| **Über Code hinaus** | Dokumente, PDFs, Bilder und Video/Audio werden alle in denselben Graphen abgebildet |
| **Local-first** | Code wird lokal mit tree-sitter geparst (kein LLM, nichts verlässt Ihren Rechner); nur der semantische Durchlauf über Dokumente/Medien ruft ein Backend auf, und auch nur, wenn Sie eines konfigurieren |

## Install

> [!IMPORTANT]
> **Offizielles Paket:** Das PyPI-Paket heißt `graphifyy` (mit doppeltem y). Andere `graphify*`-Pakete auf PyPI sind nicht zugehörig. Der CLI-Befehl ist weiterhin `graphify`.

Das offizielle Quell-Repository ist [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify).

**Schritt 1 — das Paket installieren:**

```bash
# Recommended (isolated env; if 'graphify' isn't found after, run: uv tool update-shell):
uv tool install graphifyy

# Alternatives:
pipx install graphifyy
pip install graphifyy  # may need PATH setup — see note below
```

**Schritt 2 — die Skill bei Ihrem KI-Assistenten registrieren:**

```bash
graphify install
```

Das war's. Öffnen Sie Ihren KI-Assistenten und geben Sie `/graphify .` ein

Um die Assistenten-Skill in das aktuelle Repository statt in Ihr
Benutzerprofil zu installieren, fügen Sie `--project` hinzu:

```bash
graphify install --project
graphify install --project --platform codex
```

Projektbezogene Installationen schreiben unter das aktuelle Verzeichnis, zum Beispiel
`.claude/skills/graphify/SKILL.md` oder `.agents/skills/graphify/SKILL.md` (plus ein
`references/`-Sidecar, das die Skill bei Bedarf lädt), und
geben einen `git add`-Hinweis für Dateien aus, die committet werden können.
Pro-Plattform-Befehle, die projektbezogene Installationen unterstützen, akzeptieren dasselbe Flag,
zum Beispiel `graphify claude install --project` oder `graphify codex install --project`.

> [!TIP]
> Stoßen Sie auf `command not found`, ein `pip`-Problem unter Mac/Windows, PowerShell-Quoting, `uvx`-Nutzung, PATH-Eigenheiten bei Git-Hooks oder den Strict Mode? Siehe **[Installation](https://docs.graphify.com/installation)** und **[Troubleshooting](https://docs.graphify.com/troubleshooting)**.

## Make your assistant always use the graph

Führen Sie dies einmal in Ihrem Projekt aus, nachdem Sie einen Graphen erstellt haben:

Führen Sie `graphify <platform> install` einmal in Ihrem Projekt aus, zum Beispiel `graphify claude install` oder `graphify codex install` (oder `graphify install --platform <name>`).

Dies schreibt eine kleine Konfigurationsdatei, die Ihren Assistenten anweist, bei Fragen zur Codebasis den Wissensgraphen zu konsultieren und dabei eingegrenzte Abfragen wie `graphify query "<question>"` dem Lesen des vollständigen Reports oder dem Durchsuchen roher Dateien vorzuziehen.

- **Hook-Plattformen** (Claude Code, Gemini CLI): Ein Hook wird automatisch vor suchartigen Tool-Aufrufen ausgelöst (und, bei Claude Code, bevor Quelldateien einzeln über die Read-/Glob-Tools gelesen werden) und lenkt Ihren Assistenten in Richtung des Graph-Pfads.
- **Instruktionsdatei-Plattformen** (Codex, OpenCode, Cursor usw.): Persistente Instruktionsdateien (`AGENTS.md`, `.cursor/rules/` usw.) liefern dieselbe Query-First-Anleitung.

`GRAPH_REPORT.md` steht weiterhin für eine breite Architekturübersicht zur Verfügung.

**CodeBuddy** macht dasselbe wie Claude Code: Es schreibt einen `CODEBUDDY.md`-Abschnitt, der CodeBuddy anweist, `graphify-out/GRAPH_REPORT.md` zu lesen, bevor Architekturfragen beantwortet werden, und installiert `PreToolUse`-Hooks (`.codebuddy/settings.json`), die vor Bash-Suchbefehlen und Dateilesevorgängen ausgelöst werden und stattdessen zu `graphify query` hinlenken.

**Codex** schreibt in `AGENTS.md`, was auf dieser Plattform die stets aktive Graph-Anleitung tatsächlich trägt. `graphify codex install` registriert außerdem einen `PreToolUse`-Hook in `.codex/hooks.json` (`graphify hook-check`), doch dieser Eintrag ist bewusst ein **No-op**: Codex Desktop lehnt `hookSpecificOutput.additionalContext` bei `PreToolUse` ab, sodass das Ausgeben eines Hinweises dort Bash-Tool-Aufrufe beschädigen würde. Anders als bei Claude Code, wo der Hook (`graphify hook-guard`) den Hinweis gibt, wird der Hook bei Codex ausgelöst und tut absichtlich nichts, und `AGENTS.md` ist der stets aktive Mechanismus.

**Kilo Code** installiert die Graphify-Skill nach `~/.config/kilo/skills/graphify/SKILL.md` und einen nativen `/graphify`-Befehl nach `~/.config/kilo/command/graphify.md`. `graphify kilo install` schreibt außerdem `AGENTS.md` sowie ein natives `tool.execute.before`-Plugin (`.kilo/plugins/graphify.js` + Registrierung in `.kilo/kilo.json` oder `.kilo/kilo.jsonc`), damit Kilo dasselbe stets aktive Graph-Erinnerungsverhalten über die native `.kilo`-Konfiguration erhält.

**Cursor** schreibt `.cursor/rules/graphify.mdc` mit `alwaysApply: true`, sodass Cursor es automatisch in jedes Gespräch einbezieht, ohne Hook.

Um graphify von allen Plattformen auf einmal zu entfernen: `graphify uninstall` (fügen Sie `--purge` hinzu, um auch `graphify-out/` zu löschen). Oder nutzen Sie den Pro-Plattform-Befehl (z. B. `graphify claude uninstall`).

## Common commands

```bash
/graphify .                        # build graph for current folder
/graphify ./docs --update          # re-extract only changed files
/graphify . --cluster-only         # rerun clustering without re-extracting
/graphify . --cluster-only --resolution 1.5      # more granular communities
/graphify . --cluster-only --exclude-hubs 99     # suppress utility super-hubs from god-node rankings
/graphify . --no-viz               # skip the HTML, just the report + JSON
/graphify . --wiki                 # build a markdown wiki from the graph
graphify export callflow-html      # Mermaid architecture/call-flow HTML (auto-regenerates on every git commit if hook is installed)

/graphify query "what connects auth to the database?"
/graphify path "UserService" "DatabasePool"
/graphify explain "RateLimiter"

/graphify add https://arxiv.org/abs/1706.03762   # fetch a paper and add it
/graphify add <youtube-url>                       # transcribe and add a video

graphify hook install              # auto-rebuild on commit + branch checkout (run `graphify update .` after `git pull` — see "Recommended workflow" below)
graphify merge-graphs a.json b.json              # combine two graphs

graphify prs                       # PR dashboard: CI state, review status, worktree mapping
graphify prs 42                    # deep dive on PR #42 with graph impact
graphify prs --triage              # AI ranks your review queue (uses whatever backend is configured)
graphify prs --conflicts           # PRs sharing graph communities — merge-order risk
```

## Privacy

- **Code-Dateien** — lokal via tree-sitter verarbeitet. Nichts verlässt Ihren Rechner. Ein reiner Code-Korpus benötigt keinen API-Schlüssel — `graphify extract` läuft vollständig offline. Fügen Sie bei einem gemischten Repo `--code-only` hinzu, um nur den Code zu indexieren und die Dokumente/PDFs/Bilder zu überspringen, die sonst ein LLM benötigen würden.
- **Video / Audio** — lokal mit faster-whisper transkribiert. Nichts verlässt Ihren Rechner.
- **Dokumente, PDFs, Bilder** — zur semantischen Extraktion an Ihren KI-Assistenten gesendet (über die `/graphify`-Skill, mit dem Modell, das Ihre IDE-Sitzung ausführt). Headless benötigt `graphify extract` `GEMINI_API_KEY` / `GOOGLE_API_KEY` (Gemini), `MOONSHOT_API_KEY` (Kimi), `ANTHROPIC_API_KEY` (Claude), `OPENAI_API_KEY` (OpenAI), `DEEPSEEK_API_KEY` (DeepSeek), eine laufende Ollama-Instanz (`OLLAMA_BASE_URL`), AWS-Anmeldedaten über die Standard-Provider-Kette (Bedrock – kein API-Schlüssel nötig, nutzt IAM) oder das `claude`-CLI-Binary (Claude Code – kein API-Schlüssel nötig, nutzt Ihr Claude-Abonnement). Das `--dedup-llm`-Flag nutzt denselben Schlüssel.
- **Datenresidenz** — `graphify extract` erkennt automatisch, welcher Provider zu verwenden ist, anhand des gesetzten API-Schlüssels (Priorität: Gemini → Kimi → Claude → OpenAI → DeepSeek → Azure → Bedrock → Ollama). Für Code mit Anforderungen an die Datenresidenz nutzen Sie `--backend ollama` (vollständig lokal) oder übergeben Sie ein explizites `--backend`-Flag. Kimi (`MOONSHOT_API_KEY`) leitet an Moonshot-AI-Server in China weiter.
- **Keine Telemetrie**, kein Nutzungs-Tracking, keine Analyse.
- **Query-Logging** — jeder `graphify query`-, `graphify path`-, `graphify explain`- und MCP-`query_graph`-Aufruf wird in `~/.cache/graphify-queries.log` im JSON-Lines-Format protokolliert (Zeitstempel, Frage, Korpus, zurückgegebene Knoten, Dauer). Vollständige Teilgraph-Antworten werden standardmäßig **nicht** gespeichert. Setzen Sie `GRAPHIFY_QUERY_LOG_DISABLE=1`, um sich abzumelden, oder `GRAPHIFY_QUERY_LOG=/dev/null`, um es stillzulegen, ohne den Codepfad zu deaktivieren.

## Graphify Cloud

[**Graphify Cloud**](https://app.graphify.com/login) ist die stets aktive Schicht, die auf graphify aufbaut. Statt eines Graphen, den Sie pro Ordner bei Bedarf neu erstellen, hält sie einen lebendigen Graphen über Ihren gesamten Software-Entwicklungslebenszyklus hinweg:

- **80 % weniger Tokens** — stets aktives Gedächtnis bedeutet, dass Ihre Agenten die Codebasis nicht in jeder Sitzung erneut lesen und erneut erklären müssen.
- **Monorepo und Repository-übergreifend** — ein zusammenhängender Graph über jeden Dienst und jedes Repository, kein Graph pro Ordner.
- **Formale Verifikation** — prüfen Sie Architektur- und Abhängigkeitsinvarianten gegen den lebendigen Graphen.
- **Code-Review mit Vogelperspektive auf Ihren SDLC** — sehen Sie, wie sich eine Änderung durch das gesamte System fortpflanzt, bevor Sie mergen.
- **SDLC-Konnektoren** — binden Sie Sentry, Jira und mehr ein, damit Vorfälle, Tickets und Code in einem Graphen leben.
- **Stets aktiv** — aktualisiert sich kontinuierlich im Hintergrund über Code, Dokumente und Meetings hinweg.
