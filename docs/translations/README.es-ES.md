Escribe `/graphify` en tu asistente de programación con IA y traza todo tu proyecto (código, documentos, PDF, imágenes, vídeos) en un **grafo de conocimiento** que puedes **consultar en lugar de hacer grep** por los archivos.

- **Mapeo de código gratis, totalmente local.** El código se analiza con el AST de tree-sitter: determinista, sin LLM, nada sale de tu máquina. (Los documentos, PDF, imágenes y vídeo usan el modelo de tu asistente, o una clave de API configurada, para una pasada semántica.)
- **Cada arista se explica.** Cada conexión se etiqueta como `EXTRACTED` (explícita en la fuente) o `INFERRED` (resuelta por graphify), de modo que puedes distinguir lo que se leyó directamente de lo que se infirió.
- **No es un índice vectorial.** Sin embeddings, sin almacén de vectores: un grafo real que recorres. Haz una pregunta, traza el camino entre dos cosas o explica un concepto.

**Primeros pasos** (30 segundos):

```bash
uv tool install graphifyy      # install the CLI (or: pipx install graphifyy)
graphify install               # register the skill with your AI assistant
```

Luego, en tu asistente de IA:

```
/graphify .
```

Eso es todo. Obtienes **tres archivos**:

```
graphify-out/
├── graph.html       open in any browser — click nodes, filter, search
├── GRAPH_REPORT.md  the highlights: key concepts, surprising connections, suggested questions
└── graph.json       the full graph — query it anytime without re-reading your files
```

El grafo persistido incluye `graph.schema_version` para que las integraciones puedan detectar
cambios de formato incompatibles, además de `graph.graphify_version`, que identifica la
versión de Graphify que lo produjo.

**Funciona en** Claude Code, Cursor, Codex, Gemini CLI, GitHub Copilot y más de 15 más — [elige tu plataforma](#install).

<p align="center">

Una vez construido el grafo, lo consultas en lugar de leer archivos. Salida real, graphify ejecutado sobre la base de código de FastAPI mostrada arriba:

```text
$ graphify explain "APIRouter"
Node: APIRouter
  Source:    routing.py L2210
  Community: 2
  Degree:    47

Connections (47):
  --> RequestValidationError [uses] [INFERRED]
  --> Dependant [uses] [INFERRED]
  --> .get() [method] [EXTRACTED]
  <-- __init__.py [imports] [EXTRACTED]
  ...

$ graphify path "FastAPI" "ModelField"
Shortest path (3 hops):
  FastAPI --uses--> DefaultPlaceholder <--references-- get_request_handler() --references--> ModelField
```

Cada arista lleva una **etiqueta de confianza** (`EXTRACTED` = explícita en la fuente, `INFERRED` = derivada por resolución), de modo que puedes distinguir lo que se leyó directamente de lo que se infirió. `graphify query "<question>"` devuelve un subgrafo acotado para una pregunta en lenguaje natural, y `graphify path A B` traza cómo se conectan dos cosas cualesquiera.

## What it does

Lo que obtienes de serie:

| Capacidad | Lo que obtienes |
|---|---|
| **God nodes** | Los conceptos más conectados, para que veas por dónde fluye todo |
| **Communities** | El grafo dividido en subsistemas (Leiden), con etiquetas sin LLM |
| **Enlaces entre archivos** | `calls` / `imports` / `inherits` / `mixes_in` resueltos a través de ~40 lenguajes mediante el AST de tree-sitter |
| **Query, path, explain** | Haz una pregunta, traza el camino entre dos cosas o explica un concepto, todo contra `graph.json` |
| **Justificación + ref. de docs** | Los comentarios `# NOTE:` / `# WHY:` y las citas de ADR/RFC se convierten en nodos de primera clase vinculados al código |
| **Más allá del código** | Documentos, PDF, imágenes y vídeo/audio se trazan todos en el mismo grafo |
| **Local-first** | El código se analiza localmente con tree-sitter (sin LLM, nada sale de tu máquina); solo la pasada semántica sobre documentos/medios llama a un backend, y solo si configuras uno |

## Install

> [!IMPORTANT]
> **Paquete oficial:** el paquete de PyPI es `graphifyy` (con doble y). Otros paquetes `graphify*` en PyPI no están afiliados. El comando de la CLI sigue siendo `graphify`.

El repositorio fuente oficial es [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify).

**Paso 1 — instalar el paquete:**

```bash
# Recommended (isolated env; if 'graphify' isn't found after, run: uv tool update-shell):
uv tool install graphifyy

# Alternatives:
pipx install graphifyy
pip install graphifyy  # may need PATH setup — see note below
```

**Paso 2 — registrar la skill con tu asistente de IA:**

```bash
graphify install
```

Eso es todo. Abre tu asistente de IA y escribe `/graphify .`

Para instalar la skill del asistente en el repositorio actual en lugar de en tu
perfil de usuario, añade `--project`:

```bash
graphify install --project
graphify install --project --platform codex
```

Las instalaciones con ámbito de proyecto escriben bajo el directorio actual, por ejemplo
`.claude/skills/graphify/SKILL.md` o `.agents/skills/graphify/SKILL.md` (más un
sidecar `references/` que la skill carga a demanda), e
imprimen una sugerencia de `git add` para los archivos que se pueden confirmar.
Los comandos por plataforma que admiten instalaciones con ámbito de proyecto aceptan la misma opción,
por ejemplo `graphify claude install --project` o `graphify codex install --project`.

> [!TIP]
> ¿Te topas con `command not found`, un problema de `pip` en Mac/Windows, comillas de PowerShell, el uso de `uvx`, rarezas del PATH en git-hooks o el modo estricto? Consulta **[Installation](https://docs.graphify.com/installation)** y **[Troubleshooting](https://docs.graphify.com/troubleshooting)**.

## Make your assistant always use the graph

Ejecuta esto una vez en tu proyecto después de construir un grafo:

Ejecuta `graphify <platform> install` una vez en tu proyecto, por ejemplo `graphify claude install` o `graphify codex install` (o `graphify install --platform <name>`).

Esto escribe un pequeño archivo de configuración que le indica a tu asistente que consulte el grafo de conocimiento para las preguntas sobre la base de código, prefiriendo consultas acotadas como `graphify query "<question>"` antes que leer el informe completo o hacer grep de archivos en bruto.

- **Plataformas con hooks** (Claude Code, Gemini CLI): un hook se dispara automáticamente antes de las llamadas a herramientas de tipo búsqueda (y, en Claude Code, antes de leer archivos fuente uno por uno mediante las herramientas Read/Glob) y orienta a tu asistente hacia la ruta del grafo.
- **Plataformas con archivos de instrucciones** (Codex, OpenCode, Cursor, etc.): archivos de instrucciones persistentes (`AGENTS.md`, `.cursor/rules/`, etc.) proporcionan la misma guía de consultar primero.

`GRAPH_REPORT.md` sigue disponible para una revisión amplia de la arquitectura.

**CodeBuddy** hace las dos mismas cosas que Claude Code: escribe una sección `CODEBUDDY.md` que le indica a CodeBuddy leer `graphify-out/GRAPH_REPORT.md` antes de responder preguntas de arquitectura, e instala hooks `PreToolUse` (`.codebuddy/settings.json`) que se disparan antes de los comandos de búsqueda de Bash y las lecturas de archivos, orientando en su lugar hacia `graphify query`.

**Codex** escribe en `AGENTS.md`, que es lo que realmente transporta la guía de grafo siempre activa en esta plataforma. `graphify codex install` también registra un hook `PreToolUse` en `.codex/hooks.json` (`graphify hook-check`), pero esa entrada es deliberadamente un **no-op**: Codex Desktop rechaza `hookSpecificOutput.additionalContext` en `PreToolUse`, por lo que emitir un empujón ahí rompería las llamadas a la herramienta Bash. A diferencia de Claude Code, donde el hook (`graphify hook-guard`) hace el empujón, en Codex el hook se dispara y a propósito no hace nada, y `AGENTS.md` es el mecanismo siempre activo.

**Kilo Code** instala la skill de Graphify en `~/.config/kilo/skills/graphify/SKILL.md` y un comando nativo `/graphify` en `~/.config/kilo/command/graphify.md`. `graphify kilo install` también escribe `AGENTS.md` más un plugin nativo `tool.execute.before` (`.kilo/plugins/graphify.js` + registro en `.kilo/kilo.json` o `.kilo/kilo.jsonc`), de modo que Kilo obtiene el mismo comportamiento de recordatorio de grafo siempre activo a través de la configuración nativa `.kilo`.

**Cursor** escribe `.cursor/rules/graphify.mdc` con `alwaysApply: true`, de modo que Cursor lo incluye automáticamente en cada conversación, sin necesidad de hook.

Para quitar graphify de todas las plataformas de una vez: `graphify uninstall` (añade `--purge` para borrar también `graphify-out/`). O usa el comando por plataforma (p. ej. `graphify claude uninstall`).

## What's in the report

## What files it handles

graphify analiza ~40 lenguajes de programación localmente con el AST de tree-sitter, y traza documentos, PDF, imágenes y audio/vídeo mediante una pasada semántica opcional. Lista completa: **[Supported inputs](https://docs.graphify.com/concepts/supported-inputs)**.

## Common commands

```bash
/graphify .                        # build graph for current folder
/graphify ./docs --update          # re-extract only changed files
/graphify . --cluster-only         # rerun clustering without re-extracting
/graphify . --cluster-only --resolution 1.5      # more granular communities
/graphify . --cluster-only --exclude-hubs 99     # suppress utility super-hubs from god-node rankings
/graphify . --no-viz               # skip the HTML, just the report + JSON
/graphify . --wiki                 # build a markdown wiki from the graph
graphify export callflow-html      # Mermaid architecture/call-flow HTML (auto-regenerates on every git commit if hook is installed)

/graphify query "what connects auth to the database?"
/graphify path "UserService" "DatabasePool"
/graphify explain "RateLimiter"

/graphify add https://arxiv.org/abs/1706.03762   # fetch a paper and add it
/graphify add <youtube-url>                       # transcribe and add a video

graphify hook install              # auto-rebuild on commit + branch checkout (run `graphify update .` after `git pull` — see "Recommended workflow" below)
graphify merge-graphs a.json b.json              # combine two graphs

graphify prs                       # PR dashboard: CI state, review status, worktree mapping
graphify prs 42                    # deep dive on PR #42 with graph impact
graphify prs --triage              # AI ranks your review queue (uses whatever backend is configured)
graphify prs --conflicts           # PRs sharing graph communities — merge-order risk
```

Consulta la [referencia completa de comandos](#full-command-reference) más abajo.

## Privacy

- **Archivos de código** — procesados localmente mediante tree-sitter. Nada sale de tu máquina. Un corpus solo de código no requiere ninguna clave de API — `graphify extract` se ejecuta totalmente sin conexión. En un repo mixto, añade `--code-only` para indexar solo el código y omitir los documentos/PDF/imágenes que de otro modo necesitarían un LLM.
- **Vídeo / audio** — transcritos localmente con faster-whisper. Nada sale de tu máquina.
- **Documentos, PDF, imágenes** — enviados a tu asistente de IA para la extracción semántica (a través de la skill `/graphify`, usando el modelo que ejecute tu sesión de IDE). En modo headless, `graphify extract` requiere `GEMINI_API_KEY` / `GOOGLE_API_KEY` (Gemini), `MOONSHOT_API_KEY` (Kimi), `ANTHROPIC_API_KEY` (Claude), `OPENAI_API_KEY` (OpenAI), `DEEPSEEK_API_KEY` (DeepSeek), una instancia de Ollama en ejecución (`OLLAMA_BASE_URL`), credenciales de AWS a través de la cadena de proveedores estándar (Bedrock — no necesita clave de API, usa IAM), o el binario de la CLI `claude` (Claude Code — no necesita clave de API, usa tu suscripción de Claude). La opción `--dedup-llm` usa la misma clave.
- **Residencia de datos** — `graphify extract` detecta automáticamente qué proveedor usar en función de qué clave de API esté configurada (prioridad: Gemini → Kimi → Claude → OpenAI → DeepSeek → Azure → Bedrock → Ollama). Para código con requisitos de residencia de datos, usa `--backend ollama` (totalmente local) o pasa una opción `--backend` explícita. Kimi (`MOONSHOT_API_KEY`) enruta a los servidores de Moonshot AI en China.
- **Sin telemetría**, sin seguimiento de uso, sin analítica.
- **Registro de consultas** — cada llamada `graphify query`, `graphify path`, `graphify explain` y MCP `query_graph` se registra en `~/.cache/graphify-queries.log` en formato JSON Lines (marca de tiempo, pregunta, corpus, nodos devueltos, duración). Las respuestas completas del subgrafo **no** se almacenan de forma predeterminada. Establece `GRAPHIFY_QUERY_LOG_DISABLE=1` para no participar, o `GRAPHIFY_QUERY_LOG=/dev/null` para silenciarlo sin desactivar la ruta de código.

## Graphify Cloud

[**Graphify Cloud**](https://app.graphify.com/login) es la capa siempre activa construida sobre graphify. En lugar de un grafo que reconstruyes a demanda por carpeta, mantiene un único grafo vivo a lo largo de todo tu ciclo de vida de desarrollo de software:

- **80 % menos tokens** — una memoria siempre activa significa que tus agentes dejan de releer y reexplicar la base de código en cada sesión.
- **Monorepo y multirepositorio** — un único grafo conectado en cada servicio y repositorio, no un grafo por carpeta.
- **Verificación formal** — comprueba invariantes de arquitectura y dependencias contra el grafo vivo.
- **Revisión de código con una vista de pájaro de tu SDLC** — observa cómo un cambio se propaga por todo el sistema antes de hacer merge.
- **Conectores de SDLC** — incorpora Sentry, Jira y más, para que los incidentes, los tickets y el código vivan en un único grafo.
- **Siempre activo** — se actualiza de forma continua en segundo plano a través de código, documentos y reuniones.
