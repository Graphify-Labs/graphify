Введіть `/graphify` у вашому ШІ-асистенті для програмування, і він відобразить увесь ваш проєкт (код, документи, PDF-файли, зображення, відео) у **граф знань**, який ви можете **запитувати замість grep** по файлах.

- **Карти коду безкоштовно й повністю локально.** Код розбирається за допомогою tree-sitter AST: детерміновано, без LLM, нічого не залишає вашу машину. (Документи, PDF-файли, зображення та відео використовують модель вашого асистента або налаштований ключ API для семантичного проходу.)
- **Кожне ребро пояснене.** Кожне з'єднання позначається `EXTRACTED` (явно вказане в джерелі) або `INFERRED` (визначене graphify), тож ви можете відрізнити прочитане безпосередньо від виведеного.
- **Це не векторний індекс.** Жодних вбудовувань, жодного векторного сховища: справжній граф, яким ви проходите. Поставте запитання, простежте шлях між двома речами або поясніть одне поняття.

> [!NOTE]
> **Хочете, щоб це було завжди увімкнене?** [Graphify Cloud](https://app.graphify.com/login) підтримує граф живим упродовж усього вашого SDLC: підтримка монорепозиторіїв і крос-репозиторіїв, формальна верифікація та рев'ю коду з висоти пташиного польоту над вашим SDLC, а також конектори для Sentry, Jira та інших, щоб інциденти й тикети були в одному графі з вашим кодом. **[Розпочніть безкоштовну 14-денну пробну версію на app.graphify.com](https://app.graphify.com/login)**.

```bash
uv tool install graphifyy      # install the CLI (or: pipx install graphifyy)

```

Потім у вашому ШІ-асистенті:

```
/graphify .
```

Ось і все. Ви отримуєте **три файли**:

```
graphify-out/
├── graph.html       open in any browser — click nodes, filter, search
├── GRAPH_REPORT.md  the highlights: key concepts, surprising connections, suggested questions
└── graph.json       the full graph — query it anytime without re-reading your files
```

Збережений граф містить `graph.schema_version`, щоб інтеграції могли виявляти
несумісні зміни формату, а також `graph.graphify_version`, що ідентифікує
випуск Graphify, який його створив.

## Подивіться в дії

<p align="center">
  <img src="https://raw.githubusercontent.com/Graphify-Labs/graphify/v8/docs/demo-path.svg" alt="graphify path query: a terminal asks for the shortest path between FastAPI and ModelField, and the answer lights up hop by hop across the knowledge graph" width="900">
</p>

Щойно граф побудовано, ви запитуєте його замість читання файлів. Реальний вивід, graphify запущено на кодовій базі FastAPI, показаній вище:

```text
$ graphify explain "APIRouter"
Node: APIRouter
  Source:    routing.py L2210
  Community: 2
  Degree:    47

Connections (47):
  --> RequestValidationError [uses] [INFERRED]
  --> Dependant [uses] [INFERRED]
  --> .get() [method] [EXTRACTED]
  <-- __init__.py [imports] [EXTRACTED]
  ...

$ graphify path "FastAPI" "ModelField"
Shortest path (3 hops):
  FastAPI --uses--> DefaultPlaceholder <--references-- get_request_handler() --references--> ModelField
```

Кожне ребро несе **позначку впевненості** (`EXTRACTED` = явно вказане в джерелі, `INFERRED` = виведене за допомогою резолюції), тож ви можете відрізнити прочитане безпосередньо від виведеного. `graphify query "<question>"` повертає обмежений підграф для запитання звичайною мовою, а `graphify path A B` простежує, як пов'язані будь-які дві речі.

## Що це робить

Що ви отримуєте «з коробки»:

| Можливість | Що ви отримуєте |
|---|---|
| **Божественні вузли** | Найбільш пов'язані поняття, тож ви бачите, через що все проходить |
| **Спільноти** | Граф, розбитий на підсистеми (Leiden), з мітками без LLM |
| **Міжфайлові зв'язки** | `calls` / `imports` / `inherits` / `mixes_in` розв'язуються у ~40 мовах через tree-sitter AST |
| **Запит, шлях, пояснення** | Поставте запитання, простежте шлях між двома речами або поясніть одне поняття — усе на основі `graph.json` |
| **Обґрунтування + посилання на документи** | Коментарі `# NOTE:` / `# WHY:` та цитати ADR/RFC стають повноцінними вузлами, пов'язаними з кодом |
| **Поза межами коду** | Документи, PDF-файли, зображення та відео/аудіо відображаються в той самий граф |
| **Local-first** | Код розбирається локально за допомогою tree-sitter (без LLM, нічого не залишає вашу машину); лише семантичний прохід по документах/медіа викликає бекенд, і тільки якщо ви його налаштуєте |

> [!TIP]
> Запускаєте це в багатьох репозиторіях або в монорепозиторії? [Graphify Cloud](https://app.graphify.com/login) робить це безперервно та скорочує витрати токенів агентів на 80%, з крос-репозиторними зв'язками, рев'ю коду в межах усього SDLC, формальною верифікацією та конекторами Sentry/Jira. ## Install

> [!IMPORTANT]
> **Офіційний пакет:** пакет на PyPI — це `graphifyy` (подвійна y). Інші пакети `graphify*` на PyPI не є афілійованими. Команда CLI досі `graphify`.

Офіційний репозиторій вихідного коду — [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify).

**Крок 1 — встановіть пакет:**

```bash
# Recommended (isolated env; if 'graphify' isn't found after, run: uv tool update-shell):
uv tool install graphifyy

# Alternatives:
pipx install graphifyy
pip install graphifyy  # may need PATH setup — see note below
```

**Крок 2 — зареєструйте навичку у вашому ШІ-асистенті:**

```bash
graphify install
```

Ось і все. Відкрийте свій ШІ-асистент і введіть `/graphify .`

Щоб установити навичку асистента в поточний репозиторій замість вашого
профілю користувача, додайте `--project`:

```bash
graphify install --project
graphify install --project --platform codex
```

Встановлення в межах проєкту записуються під поточним каталогом, наприклад
`.claude/skills/graphify/SKILL.md` або `.agents/skills/graphify/SKILL.md` (плюс
сайдкар `references/`, який навичка завантажує за потреби), а також
друкують підказку `git add` для файлів, які можна закомітити.
Команди для окремих платформ, що підтримують встановлення в межах проєкту, приймають той самий прапорець,
наприклад `graphify claude install --project` або `graphify codex install --project`.

> [!TIP]
> Стикаєтеся з `command not found`, проблемою `pip` на Mac/Windows, екрануванням у PowerShell, використанням `uvx`, особливостями PATH для git-хуків або суворим режимом? Див. **[Встановлення](https://docs.graphify.com/installation)** та **[Усунення несправностей](https://docs.graphify.com/troubleshooting)**.

## Зробіть так, щоб ваш асистент завжди використовував граф

Запустіть це один раз у вашому проєкті після побудови графа:

Запустіть `graphify <platform> install` один раз у вашому проєкті, наприклад `graphify claude install` або `graphify codex install` (чи `graphify install --platform <name>`).

Це записує невеликий конфігураційний файл, який каже вашому асистенту звертатися до графа знань для запитань щодо кодової бази, віддаючи перевагу обмеженим запитам на кшталт `graphify query "<question>"` над читанням повного звіту чи grep по сирих файлах.

- **Платформи з хуками** (Claude Code, Gemini CLI): хук спрацьовує автоматично перед викликами інструментів пошукового типу (і, у Claude Code, перед читанням вихідних файлів по одному через інструменти Read/Glob) та підштовхує вашого асистента до шляху графа.
- **Платформи з файлами інструкцій** (Codex, OpenCode, Cursor тощо): постійні файли інструкцій (`AGENTS.md`, `.cursor/rules/` тощо) надають те саме керівництво «спершу запит».

`GRAPH_REPORT.md` усе ще доступний для широкого огляду архітектури.

**CodeBuddy** робить ті самі дві речі, що й Claude Code: записує розділ `CODEBUDDY.md`, який каже CodeBuddy читати `graphify-out/GRAPH_REPORT.md` перед відповідями на запитання щодо архітектури, та встановлює хуки `PreToolUse` (`.codebuddy/settings.json`), що спрацьовують перед командами пошуку Bash і читанням файлів, підштовхуючи до `graphify query` натомість.

**Codex** записує в `AGENTS.md`, що на цій платформі фактично й несе завжди увімкнене керівництво графом. `graphify codex install` також реєструє хук `PreToolUse` у `.codex/hooks.json` (`graphify hook-check`), але цей запис навмисно є **no-op**: Codex Desktop відхиляє `hookSpecificOutput.additionalContext` на `PreToolUse`, тож видача підказки там зламала б виклики інструмента Bash. На відміну від Claude Code, де хук (`graphify hook-guard`) виконує підштовхування, у Codex хук спрацьовує й навмисно нічого не робить, а `AGENTS.md` є завжди увімкненим механізмом.

**Kilo Code** встановлює навичку Graphify до `~/.config/kilo/skills/graphify/SKILL.md` та нативну команду `/graphify` до `~/.config/kilo/command/graphify.md`. `graphify kilo install` також записує `AGENTS.md` плюс нативний плагін `tool.execute.before` (`.kilo/plugins/graphify.js` + реєстрація `.kilo/kilo.json` чи `.kilo/kilo.jsonc`), тож Kilo отримує таку саму поведінку завжди увімкненого нагадування про граф через нативну конфігурацію `.kilo`.

**Cursor** записує `.cursor/rules/graphify.mdc` з `alwaysApply: true`, тож Cursor автоматично включає його в кожну розмову, без потреби в хуку.

Щоб видалити graphify з усіх платформ одразу: `graphify uninstall` (додайте `--purge`, щоб також видалити `graphify-out/`). Або скористайтеся командою для окремої платформи (напр., `graphify claude uninstall`).

## Поширені команди

```bash
/graphify .                        # build graph for current folder
/graphify ./docs --update          # re-extract only changed files
/graphify . --cluster-only         # rerun clustering without re-extracting
/graphify . --cluster-only --resolution 1.5      # more granular communities
/graphify . --cluster-only --exclude-hubs 99     # suppress utility super-hubs from god-node rankings
/graphify . --no-viz               # skip the HTML, just the report + JSON
/graphify . --wiki                 # build a markdown wiki from the graph
graphify export callflow-html      # Mermaid architecture/call-flow HTML (auto-regenerates on every git commit if hook is installed)

/graphify query "what connects auth to the database?"
/graphify path "UserService" "DatabasePool"
/graphify explain "RateLimiter"

/graphify add https://arxiv.org/abs/1706.03762   # fetch a paper and add it
/graphify add <youtube-url>                       # transcribe and add a video

graphify hook install              # auto-rebuild on commit + branch checkout (run `graphify update .` after `git pull` — see "Recommended workflow" below)
graphify merge-graphs a.json b.json              # combine two graphs

graphify prs                       # PR dashboard: CI state, review status, worktree mapping
graphify prs 42                    # deep dive on PR #42 with graph impact
graphify prs --triage              # AI ranks your review queue (uses whatever backend is configured)
graphify prs --conflicts           # PRs sharing graph communities — merge-order risk
```

Див. [повний довідник команд](#full-command-reference) нижче.

## Конфіденційність

- **Файли коду** — обробляються локально через tree-sitter. Нічого не залишає вашу машину. Корпус лише з коду не потребує ключа API — `graphify extract` працює повністю офлайн. У змішаному репозиторії додайте `--code-only`, щоб індексувати лише код і пропустити документи/PDF-файли/зображення, які інакше потребували б LLM.
- **Відео / аудіо** — транскрибуються локально за допомогою faster-whisper. Нічого не залишає вашу машину.
- **Документи, PDF-файли, зображення** — надсилаються вашому ШІ-асистенту для семантичного вилучення (через навичку `/graphify`, використовуючи ту модель, яку запускає сеанс вашого IDE). Безголовий `graphify extract` потребує `GEMINI_API_KEY` / `GOOGLE_API_KEY` (Gemini), `MOONSHOT_API_KEY` (Kimi), `ANTHROPIC_API_KEY` (Claude), `OPENAI_API_KEY` (OpenAI), `DEEPSEEK_API_KEY` (DeepSeek), запущеного екземпляра Ollama (`OLLAMA_BASE_URL`), облікових даних AWS через стандартний ланцюг провайдерів (Bedrock — ключ API не потрібен, використовує IAM) або бінарного файлу `claude` CLI (Claude Code — ключ API не потрібен, використовує вашу підписку Claude). Прапорець `--dedup-llm` використовує той самий ключ.
- **Місцезнаходження даних** — `graphify extract` автоматично визначає, якого провайдера використовувати, залежно від того, який ключ API встановлено (пріоритет: Gemini → Kimi → Claude → OpenAI → DeepSeek → Azure → Bedrock → Ollama). Для коду з вимогами до місцезнаходження даних використовуйте `--backend ollama` (повністю локально) або передайте явний прапорець `--backend`. Kimi (`MOONSHOT_API_KEY`) маршрутизує на сервери Moonshot AI в Китаї.
- **Жодної телеметрії**, жодного відстеження використання, жодної аналітики.
- **Логування запитів** — кожен виклик `graphify query`, `graphify path`, `graphify explain` та MCP `query_graph` записується до `~/.cache/graphify-queries.log` у форматі JSON Lines (мітка часу, запитання, корпус, повернуті вузли, тривалість). Повні відповіді підграфа **не** зберігаються за замовчуванням. Встановіть `GRAPHIFY_QUERY_LOG_DISABLE=1`, щоб відмовитися, або `GRAPHIFY_QUERY_LOG=/dev/null`, щоб вимкнути без відключення кодового шляху.

## Graphify Cloud

[**Graphify Cloud**](https://app.graphify.com/login) — це завжди увімкнений шар, побудований поверх graphify. Замість графа, який ви перебудовуєте на вимогу для кожної теки, він підтримує один живий граф упродовж усього вашого життєвого циклу розробки ПЗ:

- **На 80% менше токенів** — завжди увімкнена пам'ять означає, що ваші агенти припиняють перечитувати й повторно пояснювати кодову базу щосеансу.
- **Монорепозиторій та крос-репозиторій** — один пов'язаний граф для кожного сервісу й репозиторію, а не граф на теку.
- **Формальна верифікація** — перевіряйте архітектурні та залежнісні інваріанти щодо живого графа.
- **Рев'ю коду з висоти пташиного польоту над вашим SDLC** — побачте, як зміна розходиться по всій системі, перш ніж зливати її.
- **Конектори SDLC** — підтягуйте Sentry, Jira та інші, щоб інциденти, тикети й код жили в одному графі.
- **Завжди увімкнено** — безперервно оновлюється у фоновому режимі по коду, документах і зустрічах.
