在你的 AI 程式設計助理中輸入 `/graphify`，它會把你的整個專案（程式碼、文件、PDF、圖片、影片）映射成一張**知識圖譜**，讓你可以**用查詢取代在檔案裡逐一 grep**。

- **程式碼映射免費，完全在地運行。** 程式碼透過 tree-sitter AST 解析：具確定性、無需 LLM，任何內容都不會離開你的機器。（文件、PDF、圖片和影片會使用你助理的模型或已設定的 API 金鑰進行一次語意解析。）
- **每一條邊都有解釋。** 每個連接都會被標記為 `EXTRACTED`（原始碼中明確存在）或 `INFERRED`（由 graphify 推斷得出），因此你能分清哪些是直接讀取的、哪些是推斷出來的。
- **這不是向量索引。** 沒有嵌入、沒有向量庫：這是一張你可以真正走訪的圖。提出一個問題、追蹤兩個事物之間的路徑，或解釋某一個概念。

圖譜建立完成後，你可以查詢它而不必再逐一讀檔案。以下是在上述 FastAPI 程式碼庫上執行 graphify 的真實輸出：

```text
$ graphify explain "APIRouter"
Node: APIRouter
  Source:    routing.py L2210
  Community: 2
  Degree:    47

Connections (47):
  --> RequestValidationError [uses] [INFERRED]
  --> Dependant [uses] [INFERRED]
  --> .get() [method] [EXTRACTED]
  <-- __init__.py [imports] [EXTRACTED]
  ...

$ graphify path "FastAPI" "ModelField"
Shortest path (3 hops):
  FastAPI --uses--> DefaultPlaceholder <--references-- get_request_handler() --references--> ModelField
```

每一條邊都帶有一個**信心標籤**（`EXTRACTED` = 原始碼中明確存在，`INFERRED` = 由解析推導得出），因此你能分清哪些是直接讀取的、哪些是推斷出來的。`graphify query "<question>"` 會針對一個自然語言問題回傳一個限定範圍的子圖，`graphify path A B` 則會追蹤任意兩個事物之間如何連接。

## 它能做什麼

開箱即用你能獲得的內容：

| 能力 | 你能獲得什麼 |
|---|---|
| **上帝節點（God nodes）** | 連接最多的概念，讓你看清一切都匯聚於何處 |
| **社群（Communities）** | 將圖譜拆分為子系統（Leiden），並帶有無需 LLM 的標籤 |
| **跨檔案連結** | 透過 tree-sitter AST，在約 40 種語言中解析 `calls` / `imports` / `inherits` / `mixes_in` |
| **查詢、路徑、解釋** | 提出問題、追蹤兩個事物之間的路徑，或解釋某一個概念，全部針對 `graph.json` 進行 |
| **理由 + 文件引用** | `# NOTE:` / `# WHY:` 註解以及 ADR/RFC 引用會成為與程式碼相連的一等節點 |
| **超越程式碼** | 文件、PDF、圖片、影片/音訊都會映射到同一張圖中 |
| **在地優先** | 程式碼在本機用 tree-sitter 解析（無需 LLM，任何內容都不離開你的機器）；只有對文件/媒體的語意解析才會呼叫後端，而且僅在你設定後才會呼叫 |

## Install

> [!IMPORTANT]
> **官方套件：** PyPI 上的套件名為 `graphifyy`（雙 y）。PyPI 上其他 `graphify*` 套件與本專案無任何關聯。CLI 命令仍為 `graphify`。

官方原始碼儲存庫是 [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify)。

**步驟 1 —— 安裝套件：**

```bash
# Recommended (isolated env; if 'graphify' isn't found after, run: uv tool update-shell):
uv tool install graphifyy

# Alternatives:
pipx install graphifyy
pip install graphifyy  # may need PATH setup — see note below
```

**步驟 2 —— 向你的 AI 助理註冊該技能：**

```bash
graphify install
```

就這樣。開啟你的 AI 助理並輸入 `/graphify .`

若要將助理技能安裝到目前的儲存庫，而非你的使用者
設定檔，請加上 `--project`：

```bash
graphify install --project
graphify install --project --platform codex
```

專案範圍的安裝會寫入目前目錄之下，例如
`.claude/skills/graphify/SKILL.md` 或 `.agents/skills/graphify/SKILL.md`（外加一個
技能按需載入的 `references/` 附帶目錄），並會
為可提交的檔案印出一條 `git add` 提示。
支援專案範圍安裝的各平台命令都接受相同的旗標，
例如 `graphify claude install --project` 或 `graphify codex install --project`。

> [!TIP]
> 遇到 `command not found`、Mac/Windows 上的 `pip` 問題、PowerShell 引號問題、`uvx` 用法、git hook 的 PATH 怪癖，或是嚴格模式問題？請參閱 **[Installation](https://docs.graphify.com/installation)** 和 **[Troubleshooting](https://docs.graphify.com/troubleshooting)**。

## 讓你的助理始終使用圖譜

建立圖譜後，在你的專案中執行一次：

在你的專案中執行一次 `graphify <platform> install`，例如 `graphify claude install` 或 `graphify codex install`（或 `graphify install --platform <name>`）。

這會寫入一個小型設定檔，告訴你的助理在回答程式碼庫問題時去查閱知識圖譜，並優先使用像 `graphify query "<question>"` 這樣的限定範圍查詢，而非讀取完整報告或對原始檔案進行 grep。

- **Hook 平台**（Claude Code、Gemini CLI）：在搜尋類工具呼叫之前（以及在 Claude Code 上，透過 Read/Glob 工具逐一讀取原始碼檔案之前）會自動觸發一個 hook，推動你的助理走圖譜這條路徑。
- **指令檔平台**（Codex、OpenCode、Cursor 等）：持久化的指令檔（`AGENTS.md`、`.cursor/rules/` 等）提供同樣的「查詢優先」指引。

`GRAPH_REPORT.md` 仍可用於寬泛的架構審查。

**CodeBuddy** 做與 Claude Code 相同的兩件事：寫入一個 `CODEBUDDY.md` 段落，告訴 CodeBuddy 在回答架構問題前先讀取 `graphify-out/GRAPH_REPORT.md`；並安裝 `PreToolUse` hook（`.codebuddy/settings.json`），它會在 Bash 搜尋命令和檔案讀取之前觸發，推動改用 `graphify query`。

**Codex** 會寫入 `AGENTS.md`，這正是該平台上真正承載始終在線圖譜指引的地方。`graphify codex install` 也會在 `.codex/hooks.json` 中註冊一個 `PreToolUse` hook（`graphify hook-check`），但該項目被刻意設為**空操作**：Codex Desktop 會拒絕 `PreToolUse` 上的 `hookSpecificOutput.additionalContext`，因此在那裡發出提示會破壞 Bash 工具呼叫。與 Claude Code 不同——在 Claude Code 上由 hook（`graphify hook-guard`）負責提示——在 Codex 上，hook 會觸發並刻意什麼都不做，而 `AGENTS.md` 才是始終在線的機制。

**Kilo Code** 會將 Graphify 技能安裝到 `~/.config/kilo/skills/graphify/SKILL.md`，並將一個原生的 `/graphify` 命令安裝到 `~/.config/kilo/command/graphify.md`。`graphify kilo install` 還會寫入 `AGENTS.md`，外加一個原生的 `tool.execute.before` 外掛（`.kilo/plugins/graphify.js` + `.kilo/kilo.json` 或 `.kilo/kilo.jsonc` 註冊），使 Kilo 能透過原生 `.kilo` 設定獲得同樣的始終在線圖譜提醒行為。

**Cursor** 會寫入 `.cursor/rules/graphify.mdc` 並設定 `alwaysApply: true`，因此 Cursor 會在每次對話中自動包含它，無需 hook。

要一次從所有平台移除 graphify：`graphify uninstall`（加上 `--purge` 還會刪除 `graphify-out/`）。或使用各平台對應的命令（例如 `graphify claude uninstall`）。

## 常用命令

```bash
/graphify .                        # build graph for current folder
/graphify ./docs --update          # re-extract only changed files
/graphify . --cluster-only         # rerun clustering without re-extracting
/graphify . --cluster-only --resolution 1.5      # more granular communities
/graphify . --cluster-only --exclude-hubs 99     # suppress utility super-hubs from god-node rankings
/graphify . --no-viz               # skip the HTML, just the report + JSON
/graphify . --wiki                 # build a markdown wiki from the graph
graphify export callflow-html      # Mermaid architecture/call-flow HTML (auto-regenerates on every git commit if hook is installed)

/graphify query "what connects auth to the database?"
/graphify path "UserService" "DatabasePool"
/graphify explain "RateLimiter"

/graphify add https://arxiv.org/abs/1706.03762   # fetch a paper and add it
/graphify add <youtube-url>                       # transcribe and add a video

graphify hook install              # auto-rebuild on commit + branch checkout (run `graphify update .` after `git pull` — see "Recommended workflow" below)
graphify merge-graphs a.json b.json              # combine two graphs

graphify prs                       # PR dashboard: CI state, review status, worktree mapping
graphify prs 42                    # deep dive on PR #42 with graph impact
graphify prs --triage              # AI ranks your review queue (uses whatever backend is configured)
graphify prs --conflicts           # PRs sharing graph communities — merge-order risk
```

## 隱私

- **程式碼檔案** —— 透過 tree-sitter 在本機處理。任何內容都不會離開你的機器。純程式碼語料無需 API 金鑰 —— `graphify extract` 完全離線執行。在混合儲存庫中，加上 `--code-only` 可僅索引程式碼，並略過那些原本需要 LLM 的文件/PDF/圖片。
- **影片 / 音訊** —— 使用 faster-whisper 在本機轉錄。任何內容都不會離開你的機器。
- **文件、PDF、圖片** —— 傳送到你的 AI 助理進行語意擷取（透過 `/graphify` 技能，使用你 IDE 工作階段所執行的任何模型）。無頭的 `graphify extract` 需要 `GEMINI_API_KEY` / `GOOGLE_API_KEY`（Gemini）、`MOONSHOT_API_KEY`（Kimi）、`ANTHROPIC_API_KEY`（Claude）、`OPENAI_API_KEY`（OpenAI）、`DEEPSEEK_API_KEY`（DeepSeek）、一個正在執行的 Ollama 實例（`OLLAMA_BASE_URL`）、透過標準提供者鏈提供的 AWS 憑證（Bedrock —— 無需 API 金鑰，使用 IAM），或者 `claude` CLI 二進位檔（Claude Code —— 無需 API 金鑰，使用你的 Claude 訂閱）。`--dedup-llm` 旗標使用相同的金鑰。
- **資料落地（Data residency）** —— `graphify extract` 會根據已設定的 API 金鑰自動偵測使用哪個提供者（優先順序：Gemini → Kimi → Claude → OpenAI → DeepSeek → Azure → Bedrock → Ollama）。對於有資料落地要求的程式碼，請使用 `--backend ollama`（完全在地）或傳入明確的 `--backend` 旗標。Kimi（`MOONSHOT_API_KEY`）會路由到位於中國的 Moonshot AI 伺服器。
- **無遙測**、無使用情況追蹤、無分析。
- **查詢記錄** —— 每一次 `graphify query`、`graphify path`、`graphify explain` 以及 MCP `query_graph` 呼叫都會以 JSON Lines 格式記錄到 `~/.cache/graphify-queries.log`（時間戳、問題、語料、回傳的節點數、耗時）。預設**不**儲存完整的子圖回應。設定 `GRAPHIFY_QUERY_LOG_DISABLE=1` 可退出，或設定 `GRAPHIFY_QUERY_LOG=/dev/null` 在不停用程式碼路徑的情況下靜音它。

## Graphify Cloud

[**Graphify Cloud**](https://app.graphify.com/login) 是建構在 graphify 之上的始終在線層。它不是一張你按資料夾按需重建的圖，而是在你的整個軟體開發生命週期中保持一張即時圖：

- **token 減少 80%** —— 始終在線的記憶意味著你的代理不必在每次工作階段重新讀取和重新解釋程式碼庫。
- **Monorepo 與跨儲存庫** —— 一張橫跨每個服務和儲存庫的連通圖，而非每個資料夾一張圖。
- **形式化驗證** —— 對照即時圖檢查架構與相依性的不變條件。
- **帶有 SDLC 全局視角的程式碼審查** —— 在合併之前就看清一處改動如何波及整個系統。
- **SDLC 連接器** —— 接入 Sentry、Jira 等，讓事故、工單和程式碼同處一張圖中。
- **始終在線** —— 在背景橫跨程式碼、文件和會議持續更新。

**[在 app.graphify.com 開始 14 天免費試用 &rarr;](https://app.graphify.com/login)**
