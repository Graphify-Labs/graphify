# Domain Docs

This repository uses a single domain context.

Before exploring, read root `GLOSSARY.md` and relevant ADRs in `docs/adr/`.
If absent, proceed silently; do not create placeholder files.
Domain-modeling creates them lazily as terms and decisions are resolved.

Use glossary vocabulary in issues, proposals, tests and explanations.
Reconsider undefined terminology or raise it during domain-modeling.

Surface conflicts with existing ADRs explicitly; never silently override them.
